# 13. 고객 온보딩 절차

신규 고객사를 Poseidon에 연동할 때 고객지원팀이 실제로 밟는 순서입니다.

## <mark style="color:blue;">전체 흐름</mark>

***

```
1. 고객사 파악        → 노드 수·제품 종류 확인
2. 고객사 등록        → 화면 [6. 고객사] + 고객사 등록
3. 인스턴스 확보       → 화면 [7. 인스턴스 관리] → 승인 또는 직접 생성
4. API 키 발급·복사    → 발급 모달에서 반드시 복사 후 닫기
5. 고객사에 안내       → 설정값 + 고객용 매뉴얼 전달
6. 방화벽 신청 요청     → 고객사 보안팀
7. 고객사 설정·재시작   → 고객사 작업
8. 연동 검증          → 화면 [4. 인스턴스]에서 UP 확인
9. 완료 통보
```

## <mark style="color:blue;">단계별 상세</mark>

***

### <mark style="color:cyan;">1. 고객사 파악</mark>

| 확인 항목         | 왜 필요한가                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HA 이중화 여부** | 노드마다 인스턴스가 별도 → **키·방화벽도 노드 수만큼**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **제품 종류**     | <mark style="color:red;">**`ODYSSEY`**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**/**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**`TWOWAY`**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**/**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**`CS`**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**/**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**`M2X`**</mark> — **판정 방식이 다릅니다** |
| **사용 채널**     | 문자 / RCS / 카카오 (또는 수신 SMS·LMS·MMS·RCS) — 검증 시 대조용                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **담당자**       | 시스템 담당자와 **보안·네트워크 담당자**를 각각 확보                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

{% hint style="warning" %}
**M2X 고객사는 미리 알고 있어야 합니다.** 자체 신호가 없어 Cypher 사이드카로 상태를 추정하므로, 검증 기준과 응대 화법이 다릅니다 ([11. 상태 판정 기준](../part-3/11.-status.md)).
{% endhint %}

### <mark style="color:cyan;">2. 고객사 등록</mark>

[6. 고객사](../part-2/6.-tenants.md) → <mark style="color:red;">**`+ 고객사 등록`**</mark> (**ADMIN만 보임**)

| 항목         | 주의                                                             |
| ---------- | -------------------------------------------------------------- |
| **고객사 키**  | 사내 규칙에 맞게 (예: <mark style="color:red;">**`COMPANY_X`**</mark>) |
| **고객사명**   | **계약서상 정식 명칭.** 전 화면에 그대로 노출되고 화면에서 수정 불가                      |
| **대표 이메일** | 장애 알림 기본 수신처                                                   |

### <mark style="color:cyan;">3\~4. 인스턴스 확보와 API 키 발급</mark>

[7. 인스턴스 관리](../part-2/7.-admin-instances.md)에서 두 경로 중 하나입니다.

| 상황                | 방법                                                                                                                                                                                                                                                                                |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 고객사가 이미 등록 요청을 보냄 | 상단 <mark style="color:red;">**`승인 대기 N건`**</mark> 배너 → <mark style="color:red;">**`검토하기`**</mark> → **승인**                                                                                                                                                                        |
| 우리가 먼저 키를 만들어 전달  | <mark style="color:red;">**`+ 인스턴스 생성`**</mark> → 고객사·서비스 선택 → <mark style="color:red;">**즉시**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**`APPROVED`**</mark><mark style="color:red;">**&#x20;**</mark><mark style="color:red;">**+ 키 발급**</mark> |

{% hint style="danger" %}
발급 모달을 닫으면 **API 키를 다시 볼 수 없습니다.** 반드시 <mark style="color:red;">**`키 복사`**</mark>를 누른 뒤 닫으십시오.

복사하지 않고 닫으려 하면 확인이 뜨는데, **`+ 인스턴스 생성`으로 방금 만든 건이면 버튼이 `닫고 폐기`이고 누르는 순간 인스턴스가 삭제됩니다.** 버튼 글자를 확인하십시오.
{% endhint %}

HA 구성이면 **노드 수만큼 인스턴스를 만들고**, 각 키가 어느 서버용인지 기록해 두십시오.

### <mark style="color:cyan;">5. 고객사에 안내</mark>

전달 내용 4가지:

| 전달물           | 내용                                                        |
| ------------- | --------------------------------------------------------- |
| **접속 주소**     | <mark style="color:red;">**`poseidon.url`**</mark> 에 넣을 값 |
| **인증 키**      | 발급된 API Key (**노드별로 어느 서버용인지 명시**)                        |
| **설정 방법 문서**  | **Odyssey 매뉴얼의 Poseidon 모니터링 연동 절차**                      |
| **방화벽 신청 문서** | [15. 아웃바운드 방화벽 안내](15.-firewall.md) — 보안·네트워크 담당자에게       |

고객이 넣어야 하는 설정 (`config/system.yml`):

```yaml
poseidon:
  enabled: true
  url: http://{{ip}}:{{port}}/api/v1/odyssey-instances
  auth-key: {{발급받은 인증 키}}
  contact-email: {{담당자 이메일}}
  heartbeat:
    interval-ms: 30000
  cypher:
    enabled: true
    coalesce-window-ms: 30000
```

{% hint style="info" %}
안내할 때 **재시작이 필요하다**는 점을 반드시 명시하십시오.&#x20;
{% endhint %}

### <mark style="color:cyan;">6. 방화벽 신청 요청</mark>

[15. 아웃바운드 방화벽 안내](15.-firewall.md)의 신청 양식을 그대로 전달합니다. HA 구성이면 **양 노드 모두** 신청 대상입니다.

### <mark style="color:cyan;">7. 고객사 설정 반영·재시작</mark>

고객사가 작업합니다. 완료 후 고객 로그에서 아래를 확인해 달라고 요청하면 검증이 빨라집니다.

```
INFO  [Poseidon - start] SUCCESS
DEBUG [Poseidon - heartbeat] OK bytes=...
INFO  [Cypher] 초기화 완료
```

### <mark style="color:cyan;">8. 연동 검증 (Poseidon 화면)</mark>

| 확인 항목                                   | 화면                                            |
| --------------------------------------- | --------------------------------------------- |
| **인스턴스가 목록에 나타났는가**                     | [4. 인스턴스](../part-2/4.-instances.md)          |
| **상태가 `UP` 인가**                         | 동일                                            |
| **하트비트가 초록(2분 이내) 으로 갱신되는가**            | 동일                                            |
| **메시지 채널 열이 계약 내용과 일치하는가**              | 동일 (ODYSSEY는 전송 규격, TWOWAY는 수신 채널, CS는 OS·버전) |
| **이벤트에 `서비스 시작`이 찍혔는가**                 | [5. 이벤트](../part-2/5.-events.md)              |
| **Cypher 카드가 `CONNECTED`인가 (수집 활성 고객)** | 인스턴스 상세 → 개요                                  |
| **HA면 두 노드 모두 올라왔는가**                   | 인스턴스 목록에서 2건 확인                               |
| **고객사 상세의 `대기(PENDING)`가 0인가**          | [6. 고객사](../part-2/6.-tenants.md) 상세          |

{% hint style="info" %}
Cypher 카드는 **첫 ERROR 또는 하트비트가 도착해야** 나타납니다. 검증 시점에 <mark style="color:red;">**`Cypher 신호가 아직 감지되지 않았습니다`**</mark>가 보이면 조금 기다렸다 다시 확인하십시오.
{% endhint %}

### <mark style="color:cyan;">9. 완료 통보</mark>

고객사에 연동 완료를 알리고, 이후 장애 시 **우리가 먼저 연락하게 된다**는 점을 안내합니다.

## <mark style="color:blue;">체크리스트 (복사해서 사용)</mark>

***

```
[ ] 1. 노드 수·제품 종류(ODYSSEY/TWOWAY/CS/M2X)·채널 확인
[ ] 2. 고객사 등록 (고객사명 = 계약서상 명칭)
[ ] 3. 인스턴스 승인 또는 직접 생성 (HA면 노드 수만큼)
[ ] 4. API 키 복사 → 안전 보관 (모달 닫기 전!)
[ ] 5. 고객사에 주소·키·설정 문서 전달 (재시작 필요 명시)
[ ] 6. 방화벽 신청서 전달 (HA면 양 노드)
[ ] 7. 고객 설정 반영·재시작 완료 확인
[ ] 8. [4. 인스턴스]에서 UP + 하트비트 초록 확인 (HA면 2건)
[ ] 9. 메시지 채널 열이 계약과 일치하는지 확인
[ ] 10. Cypher 카드 CONNECTED 확인 (수집 활성 고객)
[ ] 11. 완료 통보 + 담당자 이메일 등록 확인
```

## <mark style="color:blue;">**연동 해제 (계약 종료 등)**</mark>

***

1. 고객사에 <mark style="color:red;">**`poseidon.enabled: false`**</mark> 로 변경 후 재시작하도록 안내 (외부 통신 중단)
2. [7. 인스턴스 관리](../part-2/7.-admin-instances.md)에서 해당 인스턴스 **해지**
3. 필요 시 `삭제`까지 진행 (해지 상태에서만 가능)
4. 인스턴스를 모두 정리한 뒤에야 [6. 고객사](../part-2/6.-tenants.md)에서 고객사 삭제 가능
5. 필요 시 방화벽 정책 회수를 고객사에 안내

{% hint style="warning" %}
운영 중 고객사의 인스턴스를 사전 합의 없이 해지하면, 고객 로그에 인증 실패(`status=401`)가 계속 쌓이고 감시가 끊깁니다. 반드시 합의 후 실행하십시오.
{% endhint %}
