# 12. 고객 온보딩 절차

신규 고객사를 Poseidon에 연동할 때 고객지원팀이 실제로 밟는 순서입니다.

## 전체 흐름

```
1. 고객사 파악        → 노드 수·제품 종류 확인
2. 테넌트 등록        → Poseidon 화면 [테넌트 관리]
3. 인스턴스 승인       → Poseidon 화면 [인스턴스 관리] → API Key 발급
4. 고객사에 안내       → 설정값 + 고객용 매뉴얼 전달
5. 방화벽 신청 요청     → 고객사 보안팀
6. 고객사 설정·재시작   → 고객사 작업
7. 연동 검증          → Poseidon 화면에서 UP 확인
8. 완료 통보
```

## 단계별 상세

### 1. 고객사 파악

| 확인 항목      | 왜 필요한가                          |
| ---------- | ------------------------------- |
| HA 이중화 여부  | 노드마다 인스턴스가 별도 → 키·방화벽도 노드 수만큼   |
| 제품 종류      | Odyssey / Twoway / M2X 에 따라 판정 방식이 다름 |
| 사용 채널      | 문자 / RCS / 카카오 — 상세 화면의 발송 규격과 대조용 |
| 담당자        | 시스템 담당자와 **보안·네트워크 담당자**를 각각 확보 |

### 2. 테넌트 등록

[6. 테넌트 관리](../part-2/6.-tenants.md) → `+ 테넌트 등록`

* 테넌트 키: 사내 규칙에 맞게 (예: `tenant-012`)
* 테넌트명: **계약서상 고객사명** (대시보드에 그대로 노출됨)
* 관리자 이메일: 장애 알림 기본 수신처

### 3. 인스턴스 승인 및 API Key 발급

[5. 인스턴스 관리](../part-2/5.-instances.md) → `승인 대기 N건` → **승인**

{% hint style="danger" %}
발급 창을 닫으면 **API Key를 다시 볼 수 없습니다.** 반드시 복사 후 안전하게 보관·전달하십시오.
{% endhint %}

### 4. 고객사에 안내

전달 내용 4가지:

| 전달물                         | 내용                                                    |
| --------------------------- | ----------------------------------------------------- |
| 접속 주소                       | `poseidon.url` 에 넣을 값                                 |
| 인증 키                        | 발급된 API Key (노드별로 어느 서버용인지 명시)                        |
| 설정 방법 문서                    | **Odyssey 매뉴얼 Part 2 §16 Poseidon 모니터링 연동**           |
| 방화벽 신청 문서                   | 같은 §16 하위 **아웃바운드 방화벽 허용** — 보안·네트워크 담당자에게 전달         |

고객이 넣어야 하는 설정 (`config/system.yml`):

```yaml
poseidon:
  enabled: true
  url: http://{{ip}}:{{port}}/api/v1/odyssey-instances
  auth-key: {{발급받은 인증 키}}
  contact-email: {{담당자 이메일}}
  heartbeat:
    interval-ms: 30000
  cypher:
    enabled: true
    coalesce-window-ms: 30000
```

{% hint style="info" %}
안내할 때 **재시작이 필요하다**는 점을 반드시 명시하십시오. 설정만 바꾸고 재시작하지 않아 "연동이 안 된다"고 문의하는 경우가 가장 많습니다.
{% endhint %}

### 5. 방화벽 신청 요청

[14. 아웃바운드 방화벽 안내](14.-firewall.md) 의 신청 양식을 그대로 전달합니다. HA 구성이면 **양 노드 모두** 신청 대상입니다.

### 6. 고객사 설정 반영·재시작

고객사가 작업합니다. 완료 후 고객 로그에서 아래를 확인해 달라고 요청하면 검증이 빨라집니다.

```
INFO  [Poseidon - start] SUCCESS
DEBUG [Poseidon - heartbeat] OK bytes=...
INFO  [Cypher] 초기화 완료
```

### 7. 연동 검증 (Poseidon 화면)

| 확인 항목                             | 화면                                              |
| --------------------------------- | ----------------------------------------------- |
| 인스턴스가 목록에 나타났는가                   | [3. 대시보드](../part-2/3.-dashboard.md) / [4. 모니터링](../part-2/4.-monitoring.md) |
| 상태가 `UP` 인가                       | 동일                                              |
| 마지막 하트비트가 **30초 내(초록)** 로 갱신되는가   | 동일                                              |
| 상세 화면의 **발송 규격**이 계약 내용과 일치하는가    | [4. 모니터링](../part-2/4.-monitoring.md) 상세         |
| 오류 로그 패널이 동작하는가 (수집 활성 고객)        | 동일                                              |
| **HA면 두 노드 모두** 올라왔는가             | 모니터링 목록에서 인스턴스 2건 확인                            |

### 8. 완료 통보

고객사에 연동 완료를 알리고, 이후 장애 시 우리가 먼저 연락하게 된다는 점을 안내합니다.

## 체크리스트 (복사해서 사용)

```
[ ] 1. 노드 수·제품 종류·채널 확인
[ ] 2. 테넌트 등록 (테넌트명 = 계약서상 고객사명)
[ ] 3. 인스턴스 승인 → API Key 발급 → 복사·보관
[ ] 4. 고객사에 주소·키·설정 문서 전달 (재시작 필요 명시)
[ ] 5. 방화벽 신청서 전달 (HA면 양 노드)
[ ] 6. 고객 설정 반영·재시작 완료 확인
[ ] 7. 화면에서 UP + 하트비트 갱신 확인 (HA면 2건)
[ ] 8. 완료 통보 + 담당자 이메일 등록 확인
```

## 연동 해제 (계약 종료 등)

1. 고객사에 `poseidon.enabled: false` 로 변경 후 재시작하도록 안내 (외부 통신 중단)
2. [5. 인스턴스 관리](../part-2/5.-instances.md)에서 해당 인스턴스 **비활성화**
3. 필요 시 방화벽 정책 회수를 고객사에 안내

{% hint style="warning" %}
운영 중 고객사의 인스턴스를 사전 합의 없이 비활성화하면, 고객 로그에 인증 실패(`status=401`)가 계속 쌓이고 감시가 끊깁니다. 반드시 합의 후 실행하십시오.
{% endhint %}
