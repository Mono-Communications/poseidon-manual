# 14. 고객 설명 스크립트

고객사에 Poseidon을 설명하고 연동을 이끌어낼 때 쓰는 화법입니다. 상대가 **실무 담당자**인지 **보안·네트워크 담당자**인지에 따라 강조점이 다릅니다.

## <mark style="color:blue;">실무 담당자에게 (연동 제안)</mark>

### <mark style="color:purple;">1단계 — 문제 제기</mark>

> "지금 구조에서는 발송이 멈춰도 저희가 알 수 있는 방법이 고객사에서 연락 주시는 것뿐입니다. 그래서 인지가 늦고, 원인 파악도 그때부터 시작됩니다."

### <mark style="color:purple;">2단계 — 해결 방식</mark>

> "엔진이 30초마다 자기 상태와 운영 지표를 저희 모니터링 서버로 보내주면, 저희가 발송 대기 큐 적체나 응답 지연 같은 **장애 징후를 먼저** 보게 됩니다. 실제로 발송이 멈추기 전에 연락드릴 수 있습니다."

### <mark style="color:purple;">3단계 — 고객이 할 일 (부담이 작다는 점)</mark>

> "고객사에서 해주실 일은 세 가지입니다. 설정 파일에 주소·인증 키·담당자 이메일을 추가하고, 방화벽에서 나가는 방향 한 곳을 열어주시고, 엔진을 재시작하는 것입니다."

### <mark style="color:purple;">4단계 — 안심 포인트</mark>

> "저희가 고객사 서버로 접속하는 경로는 없습니다. 인바운드 개방도, VPN도 필요 없습니다. 발송 성능에 영향도 없고, 나중에 원하시면 설정 한 줄로 즉시 중단하실 수 있습니다."

## <mark style="color:blue;">보안·네트워크 담당자에게</mark>

***

핵심 3줄만 먼저 말합니다.

> 1. **통신은 고객사 → 저희 쪽 단방향(Outbound)** 입니다.
> 2. **인바운드 포트 개방이 필요 없고**, 저희가 고객사로 접속하는 기능 자체가 없습니다.
> 3. 나가는 데이터는 **집계 수치와 오류 정보**이며, 수신번호·메시지 본문·DB 데이터는 포함되지 않습니다.

상세 자료와 신청 양식은 [15. 아웃바운드 방화벽 안내](15.-firewall.md)를 그대로 전달합니다.

## <mark style="color:blue;">반론 대응표</mark>

***

| 고객 반론                     | 답변                                                                                                               |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **"외부에서 우리 서버에 들어오는 거냐"** | 아닙니다. 고객사 → Poseidon **단방향**입니다. 인바운드 개방이 필요 없고, 저희가 고객사로 접속하는 경로가 없습니다                                          |
| **"원격 제어가 가능한 거냐"**       | 불가능합니다. 명령을 내리거나 설정을 바꾸는 기능이 없습니다. 받기만 합니다                                                                       |
| **"발송 데이터(번호·문구)가 나가냐"**  | 나가지 않습니다. 나가는 것은 건수·지연·사용률 같은 집계 수치와 예외 정보입니다                                                                    |
| **"개인정보가 섞일 수 있냐"**       | 오류 보고에 예외 메시지와 스택트레이스 요약이 포함되므로, 로그에 개인정보를 남기는 구성이면 섞일 수 있습니다. 그래서 로그 구성 점검을 권고드리고, 원하시면 오류 수집만 끄고 지표만 보낼 수 있습니다 |
| **"계정 정보가 나가냐"**          | 계정 **식별자**만 저장됩니다. 비밀번호·시크릿은 전송 항목에 없습니다                                                                         |
| **"우리 DB에 접근하냐"**         | 접근하지 않습니다. 엔진이 이미 가진 지표를 요약해 보내는 것뿐입니다                                                                           |
| **"트래픽 부담은?"**            | 30초에 300\~500바이트, 하루 약 1\~1.5MB입니다                                                                               |
| **"장애 나면 발송이 멈추는 거냐"**    | 아닙니다. 저희 쪽 전송이 실패해도 발송은 계속됩니다. 그 기간의 지표만 유실됩니다                                                                   |
| **"방화벽을 못 열어주면?"**        | 발송은 정상 동작합니다. 다만 장애를 저희가 먼저 인지할 수 없어 대응이 고객사 연락 이후로 늦어집니다                                                        |
| **"나중에 끄고 싶으면?"**         | 설정에서 `poseidon.enabled: false` 로 바꾸고 재시작하면 즉시 외부 통신이 사라집니다                                                       |
| **"오류 수집만 끄고 싶다"**        | 가능합니다. `poseidon.cypher.enabled: false` 로 설정하면 상태·지표는 유지되고 오류 수집만 중단됩니다                                          |
| **"실시간으로 다 보이냐"**         | 30초 주기입니다. 장애 인지에는 최대 3\~4분이 걸립니다                                                                                |

## <mark style="color:blue;">장애 상황에서의 화법</mark>

***

### <mark style="color:purple;">DOWN 알림을 받고 고객에게 연락할 때</mark>

> "○○고객사 엔진의 상태 신호가 △시 △분부터 3분 이상 저희 쪽에 도달하지 않고 있습니다. 발송 자체가 중단된 것인지, 신호 경로만 막힌 것인지 확인이 필요합니다. 로그에 `[Poseidon - heartbeat FAIL]` 이 남아 있는지 확인해 주시겠습니까?"

### <mark style="color:purple;">오류 이력을 근거로 원인을 전달할 때</mark>

> "△시 △분경부터 발송 단계(`ODYSSEY_SEND`)에서 게이트웨이 응답 타임아웃이 **반복** 발생하고 있습니다. 대외 연동 구간 상태를 함께 확인해 주시면 좋겠습니다."

{% hint style="warning" %}
"**3건 발생했습니다**"가 아니라 "**3종류의 오류가 반복 발생했습니다**"로 말하십시오. 화면 건수는 30초 단위로 묶인 값입니다 ([12. 오류 수집 구조](../part-3/12.-errors.md)).
{% endhint %}

### <mark style="color:purple;">오탐이었을 때</mark>

> "확인 결과 발송에는 문제가 없었고, 네트워크 순단으로 상태 신호만 일시적으로 끊겼던 것으로 보입니다. 반복되면 알림 정확도가 떨어지니 아웃바운드 경로 안정성을 한 번 점검해 주시길 권합니다."

### <mark style="color:purple;">정상 종료였을 때</mark>

> "확인 결과 △시 △분에 정상 종료 신호가 접수되어 있었습니다. 계획된 작업이었던 것으로 보이며 장애는 아닙니다."

## <mark style="color:blue;">하지 말아야 할 설명</mark>

***

{% hint style="danger" %}
* ❌ "저희가 서버에 접속해서 봅니다" → 사실이 아니고 보안 검토를 통과하지 못합니다
* ❌ "로그를 전부 가져옵니다" → 가져오는 것은 ERROR/FATAL의 요약 정보입니다
* ❌ "실시간으로 다 보입니다" → 30초 주기이며 장애 인지에 3\~4분이 걸립니다
* ❌ "AI가 자동으로 조치해 드립니다" → 수집된 오류 이력을 분석에 **활용**하는 단계입니다. 자동 조치가 아닙니다
* ❌ "DOWN이니까 발송이 멈춘 겁니다" → 신호만 끊긴 경우도 DOWN입니다
* ❌ "설정은 저희가 원격으로 바꿔드립니다" → 고객사가 직접 수정·재시작해야 합니다
* ❌ "가동률이 99.7%입니다" → 화면의 가동률은 **이벤트 건수로 환산한 추정치**입니다. SLA 근거로 쓰지 마십시오
* ❌ "알림 설정은 화면에서 바꿀 수 있습니다" → 알림 설정 화면은 **아직 준비 중**입니다
* ❌ "API 키는 다시 알려드릴 수 있습니다" → 발급 순간에만 볼 수 있고, 분실 시 **재발급**뿐입니다
* ❌ 인증 키를 메일 본문에 그대로 노출 → 키는 인증 수단 그 자체입니다
{% endhint %}
