# 1. 접속과 계정

### <mark style="color:blue;">접속 주소</mark>

***

| 구분       | 주소                                                              |
| -------- | --------------------------------------------------------------- |
| **대시보드** | <mark style="color:red;">`http://4.217.193.23/dashboard`</mark> |
| **로그인**  | <mark style="color:red;">`http://4.217.193.23/login`</mark>     |
| **회원가입** | <mark style="color:red;">`http://4.217.193.23/signup`</mark>    |

로그인하지 않은 상태로 어떤 주소에 접근하든 자동으로 로그인 화면으로 이동하며, 로그인 후 **원래 가려던 화면으로 되돌아갑니다**.<br>

### <mark style="color:blue;">계정 만들기</mark>

***

**회원가입** 화면에서 아래 6개를 입력합니다.

| 항목          | 규칙                                                                                   |
| ----------- | ------------------------------------------------------------------------------------ |
| **아이디**     | 필수                                                                                   |
| **이름**      | 필수 (실명)                                                                              |
| **이메일**     | 필수, 이메일 형식                                                                           |
| **전화번호**    | 필수. <mark style="color:red;">`010-0000-0000`</mark> 형식 — **숫자만 입력하면 하이픈이 자동으로 붙습니다** |
| **비밀번호**    | **6\~18자, 영문 + 숫자 + 특수기호를 모두 포함**                                                    |
| **비밀번호 확인** | 위와 동일해야 함                                                                            |

가입 직후에는 <mark style="color:red;">**PENDING(승인 대기)**</mark> 상태이며 로그인할 수 없습니다. 관리자(ADMIN)가 [8. 사용자](../part-2/8.-admin-users.md) 화면에서 승인해야 사용할 수 있습니다.

{% hint style="info" %}
신규 팀원이 들어오면 ① 본인이 회원가입 → ② 관리자에게 승인 요청, 두 단계가 필요합니다. "가입했는데 로그인이 안 된다"는 문의는 <mark style="color:red;">**승인 여부를 먼저**</mark> 확인하십시오.
{% endhint %}

가입 실패 시 메시지는 원인별로 다릅니다.

| 메시지                             | 원인            |
| ------------------------------- | ------------- |
| **`이미 사용 중인 아이디입니다`**           | 아이디 중복        |
| **`이미 사용 중인 이메일입니다`**           | 이메일 중복        |
| **`회원가입에 실패했습니다. 다시 시도해 주세요.`** | 그 외 (서버 오류 등) |

### <mark style="color:blue;">로그인</mark>

***

아이디와 비밀번호를 입력합니다. 비밀번호는 화면에서 **AES로 암호화되어 전송**됩니다.

성공하면 우측 상단에 `{이름}님, 환영합니다!` 알림이 뜨고 **대시보드**로 이동합니다.

실패하면 원인에 따라 다른 안내가 나옵니다. **이 구분이 문의 응대의 첫 단서입니다.**

| 화면 표시            | 의미          | 조치                                                                                        |
| ---------------- | ----------- | ----------------------------------------------------------------------------------------- |
| **팝업** `승인 대기 중` | 아직 관리자 승인 전 | <mark style="color:red;">**ADMIN**</mark>이 [8. 사용자](../part-2/8.-admin-users.md)에서 승인     |
| **팝업** `승인 거절`   | 가입이 거절된 계정  | <mark style="color:red;">**관리자**</mark> 문의                                                |
| **팝업** `계정 잠금`   | 잠긴 계정       | <mark style="color:red;">**ADMIN**</mark>이 [8. 사용자](../part-2/8.-admin-users.md)에서 **해제** |

### <mark style="color:blue;">권한 (역할)</mark>

***

역할은 <mark style="color:red;">**ADMIN**</mark>과 <mark style="color:red;">**USER**</mark> 두 가지이며 로그인 토큰(JWT)에 담겨 옵니다. 현재 내 역할은 우측 상단 사용자 메뉴와 [9. 설정](../part-2/9.-settings.md) → 내 정보에서 확인합니다.

| 역할        | 할 수 있는 일                                                        |
| --------- | --------------------------------------------------------------- |
| **ADMIN** | 모든 화면 + **인스턴스 승인·거절·해지·API 키 발급**, **사용자 승인·잠금·해제**, 고객사 등록·삭제 |
| **USER**  | 대시보드·인스턴스·이벤트·고객사 조회, 본인 비밀번호 변경                                |

{% hint style="danger" %}
**사이드바에는 권한 필터가 없습니다.** USER 계정에서도 `인스턴스 관리`·`사용자` 메뉴가 그대로 보이지만, 클릭하면 무반응입니다. 메뉴가 보인다고 권한이 있는 것이 아닙니다.
{% endhint %}

### <mark style="color:blue;">세션 유지와 자동 로그아웃</mark>

***

로그인 정보는 브라우저에 저장되어 창을 닫았다 열어도 유지됩니다. 다만 아래 규칙으로 자동 종료됩니다.

| 규칙                                                       | 동작                                                |
| -------------------------------------------------------- | ------------------------------------------------- |
| **유휴&#x20;**<mark style="color:red;">**30분**</mark>      | 클릭·입력·스크롤이 30분간 없으면 `장시간 미사용으로 자동 로그아웃됩니다` 후 로그아웃 |
| **토큰 만료&#x20;**<mark style="color:red;">**5분 전**</mark>  | `세션 만료 임박` 알림 표시                                  |
| **토큰 만료&#x20;**<mark style="color:red;">**60초 전**</mark> | 자동 갱신 시도. 성공하면 그대로 사용, 실패하면 `세션이 만료되었습니다` 후 로그아웃  |
| **다른 탭에서&#x20;**<mark style="color:red;">**로그아웃**</mark> | 열려 있는 모든 탭이 함께 로그아웃                               |

{% hint style="info" %}
장애 추적 중 화면만 켜두고 조작하지 않으면 30분 뒤 끊깁니다. **화면 자동 갱신은 유휴 타이머를 리셋하지 않습니다.** 계속 지켜봐야 한다면 가끔 화면을 클릭하십시오.
{% endhint %}

### <mark style="color:blue;">로그아웃</mark>

***

우측 상단 **사용자 영역( 이름)** 클릭 → `로그아웃` → 확인 팝업에서 확인.<br>

### <mark style="color:blue;">비밀번호</mark>

***

* 변경은 [9. 설정](../part-2/9.-settings.md) → 비밀번호 섹션. **현재 비밀번호가 필요**합니다.
* 새 비밀번호 규칙은 가입 때와 동일 — **6\~18자, 영문 + 숫자 + 특수기호**.
* **비밀번호 초기화(분실) 기능은 화면에 없습니다.** 연구소팀에 요청해야 합니다 ([17. 에스컬레이션](../part-4/17.-escalation.md)).

{% hint style="warning" %}
Poseidon Ops 계정은 **우리 내부 운영자 계정**입니다. 고객사에 계정을 만들어 주거나 화면 주소를 공유하지 마십시오.
{% endhint %}
