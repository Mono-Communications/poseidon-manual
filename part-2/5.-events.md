# 5. 이벤트

`/events` — **최근 7일간 전 고객사에서 일어난 일**을 한 줄씩 시간순으로 보는 화면. "언제부터 이랬나", "어제 밤에 무슨 일이 있었나"를 확인하는 곳입니다.

부제: *최근 7일간의 인스턴스 이벤트 · 자동 새로고침* / 기본 **1분** 자동 갱신.

## 상단 KPI 3개

| KPI | 의미 |
| --- | --- |
| **전체 이벤트** | 조회된 전체 건수 |
| **에러 수신** | `ERROR_RECEIVED` 건수 + 전체 대비 비율 |
| **하트비트 타임아웃** | `HEARTBEAT_TIMEOUT` 건수 + 비율 |

{% hint style="info" %}
**하트비트 타임아웃 비율이 갑자기 오르면 우리 쪽 또는 네트워크 문제일 가능성**이 있습니다. 특정 고객사에 몰려 있는지, 여러 고객사에 흩어져 있는지 좌측 `고객사` 필터로 확인하십시오. 여러 고객사에 동시 발생이면 즉시 에스컬레이션 대상입니다.
{% endhint %}

## 이벤트 종류 5가지

| 화면 표시 | 내부 값 | 기본 심각도 | 언제 |
| --- | --- | --- | --- |
| **서비스 시작** | `STARTED` | INFO | 엔진이 기동 신호를 보냈을 때 |
| **서비스 종료** | `SHUTDOWN` | WARN | **정상 종료** 신호를 보냈을 때 |
| **하트비트 타임아웃** | `HEARTBEAT_TIMEOUT` | **CRITICAL** | 180초 미수신으로 DOWN 전환 |
| **에러 수신** | `ERROR_RECEIVED` | ERROR | Cypher가 예외를 보고했을 때 |
| **복구** | `RECOVERED` | INFO | 끊겼다가 다시 신호가 온 경우 |

{% hint style="danger" %}
**`서비스 종료`와 `하트비트 타임아웃`은 완전히 다른 사안입니다.**

* `서비스 종료` = 고객사가 **정상적으로 껐다** → 장애 아님
* `하트비트 타임아웃` = **신호가 끊겼다** → 조사 필요

대시보드의 `종료` 카드에는 이 둘이 섞여 있습니다. 반드시 여기서 구분하십시오.
{% endhint %}

{% hint style="info" %}
`서비스 시작`과 `복구`는 심각도와 무관하게 **초록(SUCCESS)** 으로 표시됩니다. 좋은 소식이라는 뜻입니다.
{% endhint %}

## 좌측 필터

| 필터 | 동작 |
| --- | --- |
| **검색** | 고객사명, 요약, 상세 내용을 검색 |
| **이벤트 타입** | 5종 + `전체`. 각 항목에 **건수가 함께 표시**되어 분포를 바로 볼 수 있음 |
| **심각도** | `CRITICAL` `ERROR` `WARN` `INFO` — 다시 누르면 해제 |
| **고객사** | 이벤트가 많은 고객사 순. 각 고객사별 건수 표시 |

필터를 걸면 상단에 **활성 필터 칩**이 나오고, 각 칩의 `×` 또는 `전체 초기화`로 해제합니다. 우측에 `9건 / 428건` 형태로 필터 결과 대비 전체 건수가 나옵니다.

## 이벤트 한 줄 읽는 법

| 위치 | 내용 |
| --- | --- |
| 왼쪽 점·아이콘 | 심각도 색 + 이벤트 타입 아이콘 |
| 굵은 글씨 | 이벤트 요약 (없으면 타입 이름) |
| 회색 대문자 | 이벤트 타입 코드 (`HEARTBEAT_TIMEOUT` 등) |
| 그 아래 | 상세 내용 |
| 🏢 | 고객사명 |
| 오른쪽 위 | 상대 시간 (`3분 전`) |
| 오른쪽 아래 | 절대 시각 — 오늘이면 `14:21:03`, 어제면 `어제 14:21`, 그 전이면 `07-28 14:21` |

## 조회 범위와 "더 보기"

| 항목 | 값 |
| --- | --- |
| 서버에서 가져오는 범위 | 최근 **7일**, 최대 **500건** |
| 화면에 처음 보이는 개수 | **50건** |
| `더 보기` 1회 | **50건씩** 추가 |

{% hint style="warning" %}
**7일보다 오래된 이력은 이 화면에서 볼 수 없습니다.** 그 이전 이력이 필요하면 개발팀에 조회를 요청하십시오.

또한 이벤트가 매우 많은 기간에는 **500건에서 잘릴 수 있습니다.** 이 경우 특정 고객사·타입으로 먼저 필터를 걸어 범위를 좁히십시오.
{% endhint %}

## 이 화면 활용 패턴

| 상황 | 어떻게 |
| --- | --- |
| "어제 밤 몇 시부터 끊겼나" | 고객사 필터 → 타입 `하트비트 타임아웃` → 절대 시각 확인 |
| "정상 종료였나 장애였나" | 해당 시각 근처에 `서비스 종료`가 있으면 정상 종료 |
| "복구는 됐나" | 타입 `복구` 또는 `서비스 시작` 확인 |
| "이 고객사만 문제인가" | 고객사 필터 해제 후 같은 시간대에 다른 고객사도 있는지 확인 |
| "에러가 몰린 고객사는" | 타입 `에러 수신` → 좌측 고객사 목록의 건수 비교 |
