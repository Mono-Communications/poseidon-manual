# 3. 대시보드

`/dashboard` — 로그인 직후 나오는 화면. **전 고객사 Odyssey 인스턴스의 현재 상태를 한눈에** 봅니다. 아침 업무 시작 시 가장 먼저 확인하는 화면입니다.

```
┌─────────────────────────────────────────────────────────────────┐
│ 대시보드                                    ● 30s AUTO REFRESH   │
│ Odyssey 인스턴스 실시간 현황                                       │
├───────────────────┬───────────────────┬─────────────────────────┤
│  ▦  12            │  ✔  10            │  ✕  2                   │
│  전체 인스턴스      │  실행 중           │  중지됨                  │
│                   │  ████████░░ 83%   │  ██░░░░░░░░ 17%         │
├───────────────────┴───────────────────┴─────────────────────────┤
│ ◎ Odyssey 인스턴스 현황                            전체 보기 →    │
├─────────┬──────────────┬──────┬──────┬────────┬──────────┬─────┤
│ 테넌트   │ 인스턴스       │ 버전  │ 상태  │ 문자전송 │ 하트비트   │     │
│ A고객사  │ odyssey-1.jar │1.0.0 │ UP   │ KT      │ 12초 전   │ 상세 │
│ B고객사  │ odyssey-1.jar │1.0.0 │ DOWN │ CPAAS   │ 2시간 전  │ 상세 │
└─────────┴──────────────┴──────┴──────┴────────┴──────────┴─────┘
```

### 상단 요약 카드

| 카드         | 의미                                    |
| ---------- | ------------------------------------- |
| **전체 인스턴스** | Poseidon에 등록되어 조회되는 Odyssey 인스턴스 총 개수 |
| **실행 중**    | 상태가 `UP` 인 인스턴스 수 (+ 전체 대비 비율 바)      |
| **중지됨**     | 상태가 `DOWN` 인 인스턴스 수 (+ 전체 대비 비율 바)    |

{% hint style="info" %}
HA 이중화 고객사는 **노드마다 별도 인스턴스**로 계산됩니다. 고객사 2곳이 각각 2노드면 전체 인스턴스는 4개입니다.
{% endhint %}

### 인스턴스 현황 표

| 열            | 내용                              | 보는 법                                            |
| ------------ | ------------------------------- | ----------------------------------------------- |
| **테넌트**      | 고객사명                            | 어느 고객사인지                                        |
| **인스턴스**     | Odyssey 실행 파일명 / 식별명            | 예: `odyssey-pipeline-1.0.0.jar`                 |
| **버전**       | Odyssey 버전                      | 버전이 낮으면 일부 지표가 안 올 수 있음                         |
| **상태**       | `UP`(초록) / `DOWN`(빨강) / `UNKNOWN`(회색) | 엔진 생존 상태                                        |
| **문자 전송**    | 문자 발송 경로 설정값 (예: KT, CPAAS)     | 값이 `—` 면 해당 채널 미설정                              |
| **마지막 하트비트** | 상대 시간 (`12초 전`)                 | **초록** = 정상, **빨강** = 5분 넘게 신호 없음               |
| **상세**       | 인스턴스 상세 화면으로 이동                 | 오류 로그를 보려면 여기로                                  |

### 자동 갱신

오른쪽 위 `30s AUTO REFRESH` 표시가 있으며, **30초마다 자동으로 다시 조회**됩니다. 수동 새로고침은 필요 없습니다.

### 이 화면에서 판단하는 것

| 보이는 것                              | 해석                                                   | 다음 행동                                                |
| ---------------------------------- | ---------------------------------------------------- | ---------------------------------------------------- |
| 상태 `UP`, 하트비트 초록                   | 정상                                                   | 없음                                                   |
| 상태 `UP`인데 하트비트가 **빨강(5분+)**        | 신호가 끊기기 시작함. 곧 `DOWN`으로 바뀔 수 있음                      | 잠시 후 재확인, 계속되면 고객 확인                                 |
| 상태 `DOWN`                          | 3분 이상 신호 없음 — 엔진 중단 또는 네트워크 차단                       | [15. 플레이북](../part-4/15.-playbook.md) 절차로 진단          |
| 상태 `UNKNOWN`                       | 상태를 판정할 신호가 아직 없음 (신규 등록 직후 등)                       | 잠시 후 재확인                                             |
| 여러 고객사가 **동시에** `DOWN`              | 우리 쪽 플랫폼 장애 가능성                                      | 즉시 개발팀 에스컬레이션                                        |
| 목록에 고객사가 **아예 없음**                  | 아직 한 번도 기동 신호가 오지 않음 (설정 미반영 / 방화벽 차단 / 승인 후 미기동)    | [15. 플레이북](../part-4/15.-playbook.md) "대시보드에 안 뜬다" 절차 |

{% hint style="warning" %}
`DOWN` 이라고 해서 **문자 발송이 멈췄다는 뜻은 아닙니다.** Poseidon으로 가는 신호만 끊긴 경우(방화벽 정책 변경, 네트워크 순단)에도 `DOWN`이 됩니다. 고객에게 "발송이 멈췄습니다"라고 단정하지 말고 "상태 신호가 끊겼습니다"로 전달한 뒤 확인하십시오. 자세한 이유는 [10. 상태 판정 기준](../part-3/10.-status.md) 참조.
{% endhint %}
