# 5. 인스턴스 관리 (API Key 발급)

`/instances` — **고객사 인스턴스를 승인하고 API Key를 발급하는 화면.** 고객지원팀이 연동 과정에서 실제로 "처리"하는 유일한 화면이므로 가장 정확히 알아야 합니다.

{% hint style="warning" %}
승인·거절·활성화·비활성화 버튼은 **ADMIN 계정에만** 보입니다. Operator 권한은 목록 조회만 가능합니다.
{% endhint %}

## 화면 구성

```
┌────────────────────────────────────────────────────────────────────┐
│ 인스턴스 관리                                                        │
│ API Key 발급 및 상태 관리                                            │
├────────────────────────────────────────────────────────────────────┤
│ ≡ 인스턴스 목록        ● 승인 대기 2건   [전체 보기]      총 12개      │
├────┬─────────┬────────┬────────────┬──────────┬─────┬────────────┤
│ ID │ 테넌트   │ 서비스  │ 키 프리픽스   │ 상태      │ 활성 │ 액션        │
│ 31 │ A고객사  │ODYSSEY │ odk_T1va… │ PENDING  │  ●  │ 승인 │ 거절  │
│ 30 │ B고객사  │ODYSSEY │ odk_9fKx… │ APPROVED │  ●  │ 비활성화     │
└────┴─────────┴────────┴────────────┴──────────┴─────┴────────────┘
```

| 열           | 내용                                                  |
| ----------- | --------------------------------------------------- |
| **ID**      | 인스턴스 ID                                             |
| 테넌트         | 고객사명                                                |
| 서비스         | 제품 종류 (`ODYSSEY` / `TWOWAY` 등)                      |
| **키 프리픽스**  | 발급된 API Key의 앞부분만 표시. **전체 키는 발급 순간에만 볼 수 있습니다**    |
| **상태**      | `PENDING` / `APPROVED` / `REJECTED` / `REVOKED`     |
| **활성**      | ● 초록 = 사용 가능, ● 회색 = 사용 불가                          |
| 등록일 / 만료일   | 신청 시각 / 키 만료 시각 (없으면 `—`)                           |
| 액션          | 상태에 따라 표시되는 처리 버튼 (ADMIN 전용)                        |

### 승인 대기 건 빠르게 찾기

상단에 **`● 승인 대기 N건`** 버튼이 뜨면 처리할 신청이 있다는 뜻입니다. 누르면 `PENDING` 건만 필터링되고, **전체 보기** 를 누르면 필터가 해제됩니다.

## 상태 값의 의미

| 상태           | 의미                        | 가능한 액션         |
| ------------ | ------------------------- | -------------- |
| **PENDING**  | 고객사가 신청했고 승인을 기다리는 상태     | 승인 / 거절        |
| **APPROVED** | 승인 완료 — API Key가 발급된 상태  | 비활성화 / (재)활성화  |
| **REJECTED** | 거절된 신청                    | 없음             |
| **REVOKED**  | 발급된 키를 비활성화한 상태 (사용 불가)   | 활성화            |

{% hint style="info" %}
이 화면의 상태는 **API Key 발급 절차상의 단계**입니다. 고객사 Odyssey가 실제로 돌고 있는지(`UP`/`DOWN`)는 [4. Odyssey 모니터링](4.-monitoring.md) 화면에서 봐야 합니다. `APPROVED` 인데 모니터링에 안 뜨는 것은 정상적인 조합입니다 — 키는 줬지만 고객이 아직 적용·기동하지 않은 상태입니다.
{% endhint %}

## API Key 발급 (승인) 절차

1. `PENDING` 행의 **승인** 버튼을 누릅니다.
2. 확인 창이 뜹니다 — *"인스턴스 #31 (A고객사)을 승인하시겠습니까? 승인 후 API Key가 발급됩니다."*
3. 확인하면 **API Key 발급 완료** 창이 뜨고 키 전체가 표시됩니다.
4. **복사** 버튼으로 키를 복사한 뒤, 안전한 경로로 고객사에 전달합니다.
5. **확인 완료** 를 누르면 창이 닫히고, 목록의 상태가 `APPROVED` 로 바뀝니다.

{% hint style="danger" %}
**API Key는 발급 창을 닫으면 다시 볼 수 없습니다.** 목록에는 앞부분(키 프리픽스)만 남습니다. 창을 닫기 전에 반드시 복사해서 보관·전달하십시오. 분실하면 재발급(신규 키 발급) 절차를 거쳐야 하며, 기존 키는 폐기됩니다.
{% endhint %}

### 키를 고객에게 전달할 때

| 지켜야 할 것                                                    | 이유                     |
| ---------------------------------------------------------- | ---------------------- |
| 메일 본문에 평문으로 길게 노출하지 말고, 고객사 담당자에게 직접 전달 경로로 보냅니다           | 키는 인증 수단 그 자체입니다      |
| 어느 서버(노드)에 넣을 키인지 함께 안내합니다                                 | HA 구성은 노드별로 구성이 다를 수 있음 |
| 설정 위치(`config/system.yml` 의 `poseidon.auth-key`)를 함께 안내합니다 | 고객이 어디에 넣을지 몰라 문의가 옵니다 |
| 적용 후 **Odyssey 재시작**이 필요하다고 명시합니다                          | 재시작 없이는 반영되지 않습니다      |

## 거절 / 비활성화 / 활성화

| 버튼       | 언제 쓰는가                                    | 결과                    |
| -------- | ----------------------------------------- | --------------------- |
| **거절**   | 신청이 잘못된 경우 (중복 신청, 계약 없는 고객사, 오입력)         | 상태 `REJECTED` — 키 미발급 |
| **비활성화** | 계약 종료, 키 유출 의심, 고객사 요청으로 연동을 끊어야 할 때      | 상태 `REVOKED` — 키 사용 불가 |
| **활성화**  | 비활성화했던 인스턴스를 다시 쓰게 할 때                    | 다시 사용 가능 상태로 전환       |

모든 액션은 확인 창을 거치며, 처리 후 목록이 자동으로 다시 조회됩니다.

{% hint style="warning" %}
**비활성화하면 그 고객사의 상태·지표·오류 수집이 즉시 끊깁니다.** 고객사 Odyssey는 계속 발송하지만 Poseidon 전송이 인증 실패로 떨어집니다(고객 로그에 `status=401`). 운영 중 고객사에 대해서는 반드시 사전 합의 후 실행하십시오.
{% endhint %}

## 자주 겪는 상황

| 상황                                | 확인·조치                                                                     |
| --------------------------------- | ------------------------------------------------------------------------- |
| 고객이 "키를 못 받았다"                    | 목록 상태가 `APPROVED` 인지 확인 → 발급했으나 전달 누락이면 재발급 필요 (원본은 다시 볼 수 없음)            |
| 고객 로그에 `status=401` 이 계속 남는다      | 상태가 `REVOKED` 인지, 활성 표시가 회색인지 확인 → 활성화 또는 재발급                             |
| 승인했는데 모니터링에 안 뜬다                  | 정상일 수 있음. 고객이 키 적용 + 재시작 + 방화벽 개방을 완료했는지 확인 ([15. 플레이북](../part-4/15.-playbook.md)) |
| `승인 대기` 버튼이 안 보인다                 | 대기 건이 0건이거나 ADMIN 권한이 아님                                                  |
| 같은 고객사에 인스턴스가 여러 개 보인다            | 정상. HA 이중화·다중 서버 구성은 노드마다 인스턴스가 생깁니다                                      |
