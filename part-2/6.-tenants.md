# 6. 테넌트 관리

`/tenants` — **테넌트 = 고객사**. 신규 고객사를 Poseidon에 등록하고, 고객사별로 어떤 인스턴스가 붙어 있는지 확인하는 화면입니다.

## 목록 화면

```
┌────────────────────────────────────────────────────────────────────┐
│ 테넌트 관리                                          [+ 테넌트 등록]  │
│ 고객사 테넌트 목록 및 등록                                            │
├────────────────────────────────────────────────────────────────────┤
│ ⌂ 테넌트 목록                                             총 8개     │
├────┬─────────────┬──────────┬───────────────────┬─────────┬───────┤
│ ID │ 테넌트 키     │ 테넌트명  │ 관리자 이메일        │ 인스턴스 │       │
│ 3  │ tenant-003  │ A고객사   │ admin@a.co.kr     │   2     │ 상세  │
│ 4  │ tenant-004  │ B고객사   │ it@b.com          │   1     │ 상세  │
└────┴─────────────┴──────────┴───────────────────┴─────────┴───────┘
```

| 열            | 내용                                       |
| ------------ | ---------------------------------------- |
| **ID**       | 테넌트 ID (내부 식별 번호)                        |
| **테넌트 키**    | 고객사 식별 키 (예: `tenant-003`). 시스템에서 쓰는 고유값 |
| **테넌트명**     | 고객사명. 대시보드·모니터링 화면에 표시되는 이름              |
| **관리자 이메일**  | 고객사 대표 담당자 이메일. 장애 알림 기본 수신처              |
| **인스턴스**     | 해당 고객사에 등록된 인스턴스 개수                      |
| 등록일          | 테넌트 생성 시각                                |
| 상세           | 테넌트 상세 화면으로 이동                           |

## 테넌트 등록

오른쪽 위 **`+ 테넌트 등록`** 버튼을 누르면 입력 창이 열립니다.

| 입력 항목       | 규칙 / 작성 요령                                        |
| ----------- | ------------------------------------------------- |
| **테넌트 키**   | 필수. 예: `tenant-001`. 영문·숫자·하이픈으로 짧게. **나중에 헷갈리지 않게 사내 규칙을 따르십시오** |
| **테넌트명**    | 필수. 고객사명 (한글 가능). 이 값이 대시보드에 그대로 노출됩니다            |
| **관리자 이메일** | 필수. 이메일 형식 검증. 장애 알림을 받게 되는 주소                    |

등록하면 목록이 즉시 갱신됩니다.

{% hint style="warning" %}
**테넌트명은 대시보드·모니터링 화면에 그대로 표시됩니다.** 오탈자나 임시 이름(`테스트`, `aaa`)으로 등록하면 전 팀원이 그 이름으로 보게 되므로, 계약서상 고객사명 기준으로 정확히 입력하십시오.
{% endhint %}

{% hint style="info" %}
등록 순서는 **테넌트 → 인스턴스(API Key)** 입니다. 고객사가 먼저 있어야 그 고객사의 인스턴스를 승인할 수 있습니다. 전체 순서는 [12. 고객 온보딩 절차](../part-4/12.-onboarding.md) 를 보십시오.
{% endhint %}

## 테넌트 상세

목록에서 **상세**를 누르면 `/tenants/{ID}` 로 이동합니다.

### 기본 정보

테넌트 ID, 테넌트 키, 테넌트명, 관리자 이메일, 등록일, 인스턴스 수를 보여줍니다.

### 소속 인스턴스

그 고객사에 속한 인스턴스 목록입니다.

| 열         | 내용                                              |
| --------- | ----------------------------------------------- |
| ID        | 인스턴스 ID                                         |
| 서비스       | 제품 종류 (`ODYSSEY` / `TWOWAY` 등)                  |
| 키 프리픽스    | 발급된 API Key 앞부분                                 |
| 상태        | `PENDING` / `APPROVED` / `REJECTED` / `REVOKED` |
| 활성        | ● 초록 = 사용 가능 / ● 회색 = 사용 불가                     |
| 등록일 / 만료일 | 신청 시각 / 키 만료 시각                                 |

### 이 화면을 쓰는 상황

| 상황                             | 확인 방법                                            |
| ------------------------------ | ------------------------------------------------ |
| "이 고객사에 키를 몇 개 줬지?"            | 소속 인스턴스 개수와 각 상태 확인                              |
| HA 고객사인데 한쪽만 신호가 온다            | 소속 인스턴스가 2개 다 `APPROVED`·활성인지 확인                 |
| 장애 알림 수신자를 바꿔달라는 요청            | 관리자 이메일 확인 (인스턴스별 담당자는 고객 설정의 `contact-email`)    |
| 계약 종료 고객사 정리                   | 소속 인스턴스를 [5. 인스턴스 관리](5.-instances.md)에서 비활성화 처리 |

{% hint style="info" %}
장애 알림 수신처는 두 군데에서 결정됩니다 — **테넌트의 관리자 이메일**(기본값)과 **고객사 Odyssey 설정의 `poseidon.contact-email`**(인스턴스별 담당자). 인스턴스 설정값이 있으면 그것이 우선입니다.
{% endhint %}
