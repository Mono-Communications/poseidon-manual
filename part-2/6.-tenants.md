# 6. 고객사

`/tenants` — **고객사를 등록하고 고객사별 인스턴스 현황을 확인**하는 화면. 행을 클릭하면 **고객사 상세**로 들어갑니다.

부제: *등록된 고객사와 인스턴스 현황을 관리합니다.*

{% hint style="warning" %}
**자동 갱신이 없습니다.** 최신 상태를 보려면 우측 상단 `새로고침` 버튼을 누르십시오.
{% endhint %}

{% hint style="info" %}
화면 표기는 **"고객사"** 지만, 주소와 내부 API에서는 `tenant`로 나옵니다. 같은 것입니다.
{% endhint %}

## 목록 화면

```
┌──────────────────────────────────────────────────────────────────────┐
│ 고객사                                        [⟳ 새로고침] [+ 고객사 등록]│
├────────────────────┬────────────────────────┬────────────────────────┤
│ 🏢 전체 고객사   8  │ ▤ 인스턴스 보유 6  75%  │ + 신규 (이번 달)   2    │
├────────────────────┴────────────────────────┴────────────────────────┤
│ 🔍 고객사 키, 이름 검색                            [≣ 테이블][▦ 카드]  │
├────┬────────────┬─────────┬─────────────────┬──────────┬────────┬────┤
│No. │ 고객사 키   │ 고객사명 │ 대표 이메일       │ 인스턴스  │ 등록일 │작업│
│ 1  │ COMPANY_A  │ A고객사  │ admin@a.co.kr   │   4개    │2026-03-│삭제│
│ 2  │ COMPANY_B  │ B고객사  │ it@b.com        │   0개    │2026-06-│삭제│
└────┴────────────┴─────────┴─────────────────┴──────────┴────────┴────┘
```

### 상단 3칸

| 칸 | 의미 |
| --- | --- |
| **전체 고객사** | 등록된 고객사 수 |
| **인스턴스 보유** | 인스턴스가 1개 이상인 고객사 수 + 비율 |
| **신규 (이번 달)** | 이번 달에 등록된 고객사 수 |

{% hint style="info" %}
`인스턴스 보유`가 전체보다 적으면 **등록만 하고 연동이 안 끝난 고객사**가 있다는 뜻입니다. 온보딩 미완 건을 찾는 데 유용합니다.
{% endhint %}

### 테이블 열

| 열 | 내용 |
| --- | --- |
| **No.** | 화면상 순번 (고객사 ID 아님) |
| **고객사 키** | 시스템 식별 키 (예: `COMPANY_A`) |
| **고객사명** | 계약서상 고객사명. **대시보드·인스턴스 화면에 그대로 노출됩니다** |
| **대표 이메일** | 고객사 대표 담당자 이메일 |
| **인스턴스** | 보유 인스턴스 수 |
| **등록일** | 날짜 + 시각 2줄 |
| **작업** | `삭제` (아래 참고) |

검색은 **고객사 키와 고객사명**만 대상입니다. 이메일로는 검색되지 않습니다.

`테이블` / `카드` 뷰를 전환할 수 있습니다. 카드 뷰는 고객사명·키·이메일·등록일·인스턴스 수를 카드로 보여줍니다.

목록은 **20건씩** 페이지가 나뉩니다.

## 고객사 등록 (ADMIN)

우측 상단 `+ 고객사 등록` — **ADMIN에게만 보입니다.**

| 항목 | 필수 | 예시 |
| --- | --- | --- |
| **고객사 키** | ✅ | `COMPANY_X` |
| **고객사명** | ✅ | `X사` |
| **대표 이메일** | ✅ | `admin@company.co.kr` |

세 개를 모두 채우지 않으면 `모든 필드를 입력해 주세요.` 경고가 나옵니다. 등록되면 `고객사가 등록되었습니다.` 후 목록이 갱신됩니다.

{% hint style="warning" %}
**고객사명은 계약서상 정식 명칭으로 입력하십시오.** 이 값이 대시보드·인스턴스·이벤트 전 화면에 그대로 표시되며, 나중에 화면에서 수정하는 기능이 없습니다.
{% endhint %}

## 고객사 삭제 (ADMIN)

| 조건 | 결과 |
| --- | --- |
| USER 계정 | 버튼 **비활성** |
| **인스턴스가 1개 이상** | 버튼 **비활성** — 툴팁 `인스턴스가 있는 고객사는 삭제할 수 없습니다` |
| ADMIN + 인스턴스 0개 | 확인 팝업 후 삭제 |

{% hint style="danger" %}
인스턴스가 있는 고객사를 정리하려면 **[7. 인스턴스 관리](7.-admin-instances.md)에서 인스턴스를 먼저 해지·삭제**해야 합니다. 운영 중 고객사에는 절대 사전 합의 없이 하지 마십시오.
{% endhint %}

목록에서 행(또는 카드)을 클릭하면 열립니다 (`/tenants-detail?id=…`). **사이드바에는 없는 화면**이며, 탭으로 쌓입니다. 좌측 상단 `← 돌아가기`로 복귀.

## 상단 정보

고객사명, 고객사 키, 대표 이메일, 등록일, **관제 시작 N일**(등록 후 경과일).

## KPI 4개 — 여기 숫자는 인스턴스 화면과 기준이 다릅니다

{% hint style="danger" %}
**이 화면의 `활성(UP)` / `다운(DOWN)`은 하트비트 기준이 아닙니다.**

* `활성(UP)` = 상태가 `APPROVED` **이면서** 활성 플래그가 켜진 인스턴스
* `다운(DOWN)` = 상태가 `APPROVED` 이지만 활성 플래그가 꺼진 인스턴스

즉 **등록·활성 기준**입니다. 엔진이 실제로 살아있는지는 [4. 인스턴스](4.-instances.md) 화면에서 확인해야 합니다. **두 화면의 UP/DOWN 숫자가 다를 수 있고, 그것은 오류가 아닙니다.**
{% endhint %}

| KPI | 기준 |
| --- | --- |
| **전체 인스턴스** | 보유 대수 + 서비스별 내역 (`ODYSSEY 2 · TWOWAY 1 · CS 1 · M2X n`) |
| **활성 (UP)** | `APPROVED` + 활성 |
| **다운 (DOWN)** | `APPROVED` + 비활성 |
| **대기 (PENDING)** | 승인 대기 중인 등록 요청 수 |

## 인스턴스 헬스맵

인스턴스마다 카드 하나. 등록 절차상의 상태를 봅니다.

| 배지 | 의미 |
| --- | --- |
| `PENDING` | 승인 대기 (카드가 주황 계열로 강조) |
| `REJECTED` / `REVOKED` | 거절·해지 (회색 처리) |
| `UP` | 승인 + 활성 |
| `DOWN` | 승인 + 비활성 |

카드 내용: 서비스 칩, 이름, **키 접두사**, 생성일, (있으면) 만료일.

`APPROVED` 상태인 카드에만 `인스턴스 상세 →` 링크가 나오고, 누르면 [인스턴스 상세](4.-instances.md#인스턴스-상세)로 갑니다.

인스턴스가 없으면 `등록된 인스턴스가 없습니다 / 인스턴스 관리 페이지에서 새 인스턴스를 추가하세요.`가 표시됩니다.

## 이 화면 활용 패턴

| 상황 | 어떻게 |
| --- | --- |
| "이 고객사 연동 다 끝났나?" | `대기(PENDING)`가 0인지, 헬스맵에 `PENDING` 카드가 없는지 확인 |
| "HA 2노드 다 등록됐나?" | 헬스맵의 카드 수가 예상 노드 수와 맞는지 확인 |
| "어떤 서비스를 쓰는 고객사인가?" | `전체 인스턴스` 카드의 서비스별 내역 |
| "API 키가 언제 만료되나?" | 헬스맵 카드의 만료일 |
