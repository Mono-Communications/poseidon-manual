# 4. Odyssey 모니터링

`/monitoring` — 인스턴스 상태 목록과 **인스턴스별 오류 로그**를 보는 화면. 고객 장애 문의를 받았을 때 실제로 파고드는 곳입니다.

## 목록 화면

```
┌─────────────────────────────────────────────────────────────────┐
│ Odyssey 모니터링                        ● UP 10    ● DOWN 2      │
│ 인스턴스 실시간 상태 현황                                          │
├────┬─────────┬──────────────┬───────┬──────┬───────────┬───────┤
│ ID │ 테넌트   │ 인스턴스       │ 버전   │ 상태  │ 하트비트    │       │
│ 12 │ A고객사  │ odyssey-1.jar │ 1.0.0 │ UP   │ 8초 전     │ 상세  │
│ 13 │ B고객사  │ odyssey-1.jar │ 1.0.0 │ DOWN │ 3시간 전   │ 상세  │
└────┴─────────┴──────────────┴───────┴──────┴───────────┴───────┘
```

| 열            | 내용                                              |
| ------------ | ----------------------------------------------- |
| **ID**       | 인스턴스 ID. **고객 문의·개발팀 에스컬레이션 시 반드시 이 번호를 알려줍니다** |
| 테넌트          | 고객사명                                            |
| 인스턴스         | Odyssey 실행 파일명 / 식별명                            |
| 버전           | Odyssey 버전                                      |
| 상태           | `UP` / `DOWN` / `UNKNOWN`                       |
| 마지막 하트비트     | 상대 시간                                           |
| 상세           | 인스턴스 상세 화면으로 이동                                 |

오른쪽 위 칩으로 **UP / DOWN 개수**를 바로 확인할 수 있고, 목록은 **30초마다 자동 갱신**됩니다.

## 인스턴스 상세 화면

목록에서 **상세**를 누르면 `/monitoring/{ID}` 로 이동합니다.

### 기본 정보

| 항목           | 설명                                             |
| ------------ | ---------------------------------------------- |
| 인스턴스 ID      | 내부 식별 번호                                       |
| 테넌트          | 고객사명                                           |
| 인스턴스명        | Odyssey 실행 파일명 / 식별명                           |
| 버전           | Odyssey 버전                                     |
| 마지막 하트비트     | 상대 시간 (`12초 전`)                                |
| 상태 태그        | 오른쪽 위 `UP` / `DOWN` 표시                         |
| **발송 규격**    | **문자 / RCS / 카카오** 세 채널의 발송 경로 설정값. 미설정이면 `미설정` |

{% hint style="info" %}
**발송 규격**은 그 고객사가 실제로 어떤 채널을 쓰는지 알려줍니다. "카카오가 안 나간다"는 문의를 받았을 때, 카카오가 `미설정`이면 애초에 그 채널을 안 쓰는 구성입니다.
{% endhint %}

### 오류 로그

아래쪽 패널에 해당 인스턴스에서 수집된 오류가 최신순으로 표시됩니다.

| 열           | 내용                                                              |
| ----------- | --------------------------------------------------------------- |
| **심각도**     | `CRITICAL`(빨강) / `ERROR`(주황)                                    |
| **서브시스템**   | 오류가 난 기능 영역 (예: `ODYSSEY_SEND`, `ODYSSEY_DB`, `ODYSSEY_NETWORK`) |
| **예외 클래스**  | 예: `java.net.SocketTimeoutException` (길면 마우스를 올려 전체 확인)         |
| **메시지**     | 예외 메시지 (길면 마우스를 올려 전체 확인)                                       |
| **발생 시각**   | 절대 시간                                                           |
| 패널 오른쪽 `총 N건` | 조회된 오류 건수                                                       |

서브시스템 값으로 **어느 단계에서 깨졌는지** 바로 좁힐 수 있습니다.

| 서브시스템               | 의미            | 흔한 원인                       |
| ------------------- | ------------- | --------------------------- |
| `ODYSSEY_SEND`      | 발송 단계         | 게이트웨이 응답 실패·타임아웃           |
| `ODYSSEY_NETWORK`   | 게이트웨이 HTTP 통신 | 대외 연동 구간 장애, 인증 만료          |
| `ODYSSEY_DB`        | DB 접근         | 커넥션 부족, 데드락, 쿼리 오류          |
| `ODYSSEY_COLLECT` / `ODYSSEY_FETCH` | 발송 대상 수집·폴링   | DB 지연, 테이블 설정 문제            |
| `ODYSSEY_ROUTE`     | 채널 라우팅        | 세션·계정 설정 불일치                |
| `ODYSSEY_AUTH`      | 세션 인증         | 인증 파일·계정 정보 문제              |
| `ODYSSEY_PIPELINE`  | 위에 해당하지 않는 전반 | 기타                          |

전체 분류 규칙은 [11. 오류 수집 구조](../part-3/11.-errors.md) 에 있습니다.

{% hint style="warning" %}
**이 화면은 자동 갱신되지 않습니다.** 들어간 시점의 데이터이므로, 진행 중인 장애를 추적할 때는 브라우저를 새로고침하거나 목록으로 나갔다 다시 들어와야 합니다.
{% endhint %}

### 오류 로그를 읽을 때 주의

* 동일 오류가 폭주하면 **30초 단위로 묶여** 1건으로 올라옵니다. 화면의 건수가 실제 발생 횟수보다 적을 수 있습니다.
* 인스턴스가 `DOWN` 인 동안 발생한 오류는 **수집되지 않습니다.** "죽어 있는데 오류가 안 남았다"는 정상 동작입니다.
* 오류가 하나도 없는데 발송이 안 된다면, 오류 수집이 꺼져 있거나(고객 설정) 애초에 예외가 아닌 원인(설정 오류, 발송 대상 없음)일 수 있습니다.

### 이 화면에서 고객에게 전달할 내용

1. **언제부터** — 마지막 하트비트 / 오류 발생 시각
2. **어디가** — 서브시스템 (발송 / DB / 게이트웨이 통신)
3. **무엇이** — 예외 클래스·메시지 요약
4. **권장 조치** — 해당 구간 점검 요청 (예: "DB 커넥션 부족으로 보입니다. DB 상태 확인 부탁드립니다")
