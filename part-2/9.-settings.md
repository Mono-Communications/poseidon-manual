# 9. 설정

`/settings` — **로그인한 본인 계정**의 정보 확인과 비밀번호 변경. 시스템 설정이나 고객사 설정을 바꾸는 화면이 **아닙니다.**

부제: *계정 정보와 비밀번호를 관리합니다.*

```
┌────────────┬────────────────────────────────────────────────────┐
│ 👥 내 정보  │ 내 정보                                             │
│ 🔒 비밀번호 │  ⬤ 박서연                                           │
│ 🔔 알림 SOON│    아이디 csmain · [ADMIN]                          │
│            │  ─────────────────────────────────────────────     │
│            │  아이디  csmain                                     │
│            │  이름    박서연                                      │
│            │  역할    ADMIN                                      │
│            ├────────────────────────────────────────────────────┤
│            │ 비밀번호 변경                                        │
│            │  현재 비밀번호 [ ●●●●●●●● ]                          │
│            │  새 비밀번호   [ ●●●●●●●● ]                          │
│            │    ⓘ 6~18자, 영문 + 숫자 + 특수기호를 모두 포함해야 합니다│
│            │  새 비밀번호 확인 [ ●●●●●●●● ]                        │
│            │                        [취소] [비밀번호 변경]         │
│            ├────────────────────────────────────────────────────┤
│            │ 알림                          COMING SOON            │
└────────────┴────────────────────────────────────────────────────┘
```

왼쪽 목록에서 항목을 누르면 해당 섹션으로 스크롤됩니다.

## 내 정보

| 항목 | 내용 |
| --- | --- |
| **아이디** | 로그인 ID |
| **이름** | 가입 시 입력한 이름 |
| **역할** | `ADMIN` / `USER` |

{% hint style="info" %}
**"관리자 메뉴를 눌렀는데 403이 뜬다"**는 문의를 받으면 여기서 역할부터 확인하십시오. `USER`면 정상 동작입니다.
{% endhint %}

이 화면에서는 **조회만 가능**합니다. 이름·이메일·전화번호를 수정하는 기능은 없습니다.

## 비밀번호 변경

| 입력 | 규칙 |
| --- | --- |
| **현재 비밀번호** | 필수. 틀리면 변경 거부 |
| **새 비밀번호** | **6~18자, 영문 + 숫자 + 특수기호를 모두 포함** |
| **새 비밀번호 확인** | 새 비밀번호와 일치해야 함 |

성공하면 `비밀번호가 변경되었습니다.` 후 입력칸이 비워집니다. 비밀번호는 **AES로 암호화되어 전송**됩니다.

{% hint style="warning" %}
**현재 비밀번호를 모르면 변경할 수 없습니다.** 비밀번호 분실 시 초기화 기능은 화면에 없으므로 개발팀에 요청해야 합니다 ([17. 에스컬레이션](../part-4/17.-escalation.md)).
{% endhint %}

각 입력칸 오른쪽 아이콘을 누르면 입력한 내용을 잠시 볼 수 있습니다.

## 알림 — 아직 동작하지 않습니다

`COMING SOON` 상태입니다.

> CRITICAL · ERROR 이벤트 발생 시 이메일 / Slack / Webhook으로 알림을 받을 수 있는 기능을 준비 중입니다.

준비 중 항목: **이메일 / Slack / Webhook / 알림 규칙 / 조용한 시간**

{% hint style="danger" %}
**상단바의 🔔 알림 아이콘도 아직 동작하지 않습니다.**

현재 장애 알림은 이 화면이 아니라 **서버 설정에 따라 고객사 담당자 이메일로 발송**됩니다. 알림 수신처를 바꾸거나 임계값을 조정해 달라는 요청은 화면에서 처리할 수 없으므로 개발팀에 접수하십시오.

고객에게 **"설정에서 알림을 켜고 끌 수 있다"고 안내하지 마십시오.**
{% endhint %}

## 이 화면에 없는 기능 (자주 오해받는 것)

| 요청 | 실제 |
| --- | --- |
| 알림 켜기/끄기, 수신처 변경 | ❌ 준비 중 → 개발팀 |
| 이름·이메일·전화번호 수정 | ❌ 기능 없음 |
| 다른 사용자 권한 변경 | ❌ → 개발팀 ([8. 사용자](8.-admin-users.md)에도 없음) |
| 비밀번호 초기화 | ❌ → 개발팀 |
| 고객사 알림 임계값 조정 | ❌ 서버 설정 → 개발팀 |
| 다크/라이트 모드 | ✅ **상단바 🌙 / ☀ 아이콘** (설정 화면 아님) |
