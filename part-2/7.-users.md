# 7. 사용자 관리

`/users` — **우리 팀 운영자 계정**을 승인·관리하는 화면입니다. 고객사 계정이 아니라 Poseidon 화면에 로그인하는 내부 계정입니다.

{% hint style="warning" %}
**ADMIN 권한 전용 화면입니다.** Operator 계정에는 사이드바에 메뉴 자체가 보이지 않습니다.
{% endhint %}

## 화면 구성

```
┌────────────────────────────────────────────────────────────────────┐
│ 사용자 관리                          ● PENDING 1    ● ACTIVE 6      │
│ 운영자 계정 승인 및 관리                                              │
├────────────────────────────────────────────────────────────────────┤
│ 사용자 목록                                              총 7명      │
├────┬──────────┬────────────────┬────────────┬─────────┬──────┬────┤
│ ID │ 아이디    │ 이메일           │ 연락처      │ 상태     │ 권한  │액션 │
│ 7  │ newcs    │ cs2@mono.co.kr │ 010-…      │ PENDING │ USER │승인/거절│
│ 6  │ csmain   │ cs@mono.co.kr  │ 010-…      │ ACTIVE  │ USER │잠금/해제│
└────┴──────────┴────────────────┴────────────┴─────────┴──────┴────┘
```

| 열       | 내용                                                    |
| ------- | ----------------------------------------------------- |
| ID      | 사용자 ID                                                |
| 아이디     | 로그인 계정명                                               |
| 이메일     | 가입 시 입력한 이메일                                          |
| 연락처     | 가입 시 입력한 전화번호                                         |
| **상태**  | `PENDING` / `ACTIVE` / `REJECTED` / `SUSPENDED` 등     |
| **권한**  | `ADMIN` / `USER`                                      |
| 가입일     | 회원가입 시각                                               |
| **액션**  | `PENDING` 이면 **승인 / 거절**, 그 외에는 **잠금 / 해제**           |

상단 칩으로 **승인 대기(PENDING) 수와 활성(ACTIVE) 수**를 바로 볼 수 있습니다.

## 계정 승인 절차

1. 신규 팀원이 `/signup` 에서 회원가입합니다 → 상태 `PENDING`
2. 이 화면에서 해당 행의 **승인** 을 누릅니다 → 로그인 가능
3. 잘못된 가입이면 **거절** 을 누릅니다 → 상태 `REJECTED`

{% hint style="info" %}
승인 전에는 로그인이 되지 않습니다. "가입했는데 로그인이 안 된다"는 팀원 문의는 이 화면에서 `PENDING` 여부를 먼저 확인하십시오.
{% endhint %}

## 잠금 / 해제

| 버튼     | 동작                       | 쓰는 상황                                    |
| ------ | ------------------------ | ---------------------------------------- |
| **잠금** | 계정을 일정 시간 사용 불가로 전환 (기본 30분) | 퇴사·휴직·보안 이슈, 계정 오사용 확인 중                 |
| **해제** | 잠금을 즉시 해제                | 로그인 실패 반복으로 자동 잠긴 계정을 풀어줄 때, 잠금 사유가 해소됐을 때 |

로그인 실패가 반복되면 계정이 자동으로 잠길 수 있습니다. 이 경우에도 같은 **해제** 버튼으로 풉니다.

## 권한 부여 원칙

| 권한        | 부여 대상                        | 할 수 있는 일                                    |
| --------- | ---------------------------- | ------------------------------------------- |
| **ADMIN** | 팀 리드 / 승인 권한을 위임받은 인원 최소한으로  | 사용자 승인, **인스턴스 승인·API Key 발급**, 활성/비활성 전환   |
| **USER**  | 일반 고객지원팀원                    | 대시보드·모니터링 조회, 인스턴스·테넌트 조회, 테넌트 등록, 본인 설정 변경 |

{% hint style="warning" %}
ADMIN은 **고객사 API Key를 발급·폐기할 수 있는 권한**입니다. 필요한 인원에게만 부여하고, 퇴사·직무 변경 시 즉시 잠금 처리하십시오.
{% endhint %}

## 주의 사항

* 이 화면은 **자동 갱신되지 않습니다.** 액션 후에는 목록이 다시 조회되지만, 다른 사람이 만든 신규 가입 건을 보려면 새로고침이 필요합니다.
* 여기 등록되는 계정은 전부 **내부 운영자**입니다. 고객사에 계정을 만들어 주지 마십시오 ([1. 접속과 계정](../part-1/1.-access.md) 참조).
* 계정 상태와 인스턴스 상태(`APPROVED` 등)는 별개입니다. 헷갈리면 [2. 화면 구조](../part-1/2.-layout.md) 의 상태 값 구분 표를 보십시오.
