# 4. 인스턴스

`/instances` — **고객사 엔진이 지금 살아있는지** 보는 화면. 그리고 행을 클릭해 들어가는 **인스턴스 상세**가 장애 원인을 실제로 파고드는 곳입니다.

부제: *Odyssey · Twoway · CS 실시간 상태 · 자동 갱신* / 기본 **30초** 자동 갱신.

{% hint style="warning" %}
이 화면의 `UP` / `DOWN`은 **하트비트 기준 엔진 생존 상태**입니다. API 키 승인 상태(`APPROVED` 등)와는 다릅니다 — 그건 [7. 인스턴스 관리](7.-admin-instances.md)에서 봅니다.
{% endhint %}

## 목록 화면

```
┌────────────────────────────────────────────────────────────────────────┐
│ 인스턴스                                            [30초 ▾] [⟳]       │
├────────────────────┬────────────────────┬──────────────────────────────┤
│ ▤ 전체 인스턴스  12 │ ✓ UP · 실행 중 10 83%│ ✕ DOWN · 점검 필요  2  17%   │
├────────────────────┴────────────────────┴──────────────────────────────┤
│ 서비스 [전체][ODYSSEY][TWOWAY][CS][M2X]            🔍 인스턴스명, 고객사 │
├─────────┬────────┬──────────────┬──────┬─────────────────┬──────┬──────┤
│ 고객사   │ 서비스  │ 인스턴스      │ 버전  │ 메시지 채널       │ 상태  │하트비트│
│ A고객사  │ODYSSEY │ odyssey-1    │1.2.0 │ 문자 KT · RCS KT │ ● UP │ 12초 전│
│ B고객사  │TWOWAY  │ twoway-1     │1.0.3 │ SMS LMS ·3개 계정 │ ● UP │ 8초 전 │
│ C고객사  │ M2X    │ m2x-legacy ⚪ │0.9.1 │ -                │ ●DOWN│ 14:02 │
└─────────┴────────┴──────────────┴──────┴─────────────────┴──────┴──────┘
```

### 상단 3칸 — 클릭하면 필터

| 칸 | 내용 | 클릭 시 |
| --- | --- | --- |
| **전체 인스턴스** | 총 대수 | 필터 해제 |
| **UP · 실행 중** | UP 대수 + 비율 | UP만 보기 |
| **DOWN · 점검 필요** | DOWN 대수 + 비율 | DOWN만 보기 |

같은 칸을 다시 누르면 필터가 풀립니다. 대시보드의 `실행 중` / `종료` 카드를 클릭해 들어오면 해당 필터가 **이미 걸린 상태**로 열립니다.

### 서비스 필터와 검색

* 서비스 칩: `전체` `ODYSSEY` `TWOWAY` `CS` `M2X` — 하나만 선택 가능, 다시 누르면 해제
* 검색창: **인스턴스명과 고객사명**을 검색합니다 (버전·채널은 검색 안 됨)

### 테이블 열

| 열 | 내용 |
| --- | --- |
| **고객사** | 고객사명. 클릭 정렬 가능 |
| **서비스** | 서비스 타입 칩 |
| **인스턴스** | 인스턴스명 + 배지 (아래 설명) |
| **버전** | 엔진 버전 |
| **메시지 채널** | 서비스 타입에 따라 내용이 다름 (아래 표) |
| **상태** | `● UP` (초록) / `● DOWN` (빨강). DOWN이면 옆에 **끊긴 지 얼마나 됐는지** 함께 표시 |
| **하트비트** | UP이면 `12초 전`, **DOWN이면 마지막으로 받은 시각**(`14:02`) |

기본 정렬은 **UP 우선 → 마지막 하트비트 최신순**. 열 제목을 눌러 고객사·상태·하트비트로 다시 정렬할 수 있습니다.

행 아무 곳이나 클릭하면 **인스턴스 상세**로 이동합니다.

### 인스턴스명 옆 배지 2종

| 배지 | 의미 |
| --- | --- |
| `Limited Visibility` | **M2X 전용.** 자체 라이프사이클 신호가 없어 Cypher 하트비트 + 로그 활동으로 상태를 **추정**한다는 뜻 |
| 작은 점 (⚪) | **Cypher 에이전트가 붙어 있음.** 마우스를 올리면 `Cypher SIDECAR · CONNECTED` 처럼 모드와 상태가 나옴 |

점 색: 초록 `CONNECTED` / 주황 `STALE`(응답 없음) / 회색 `UNKNOWN`.

### 메시지 채널 열 읽는 법

| 서비스 | 표시 | 의미 |
| --- | --- | --- |
| **ODYSSEY** | `문자 KT` `RCS CPAAS` `카카오 MN` | 채널별 **전송 규격(사업자)**. 설정된 채널만 표시 |
| **TWOWAY** | `SMS` `LMS` `MMS` `RCS` + `· 3개 계정` | 수신 채널(회색 = 비활성) + tw 계정 수 |
| **CS** | `Windows 11` `v2.4.1` | OS와 앱 버전 |
| **M2X** | `-` | 표시 항목 없음 |

{% hint style="info" %}
온보딩 검증 때 **이 열이 계약 내용과 맞는지** 확인하십시오. 고객이 "RCS도 쓰기로 했는데"라고 하면 여기 RCS 칩이 있는지 보면 됩니다.
{% endhint %}

# 인스턴스 상세

목록에서 행을 클릭하면 열립니다 (`/instances-detail?id=…`). **사이드바에는 없는 화면**이며, 열 때마다 상단에 탭으로 쌓입니다.

기본 **1분** 자동 갱신. 좌측 상단 `← 돌아가기`로 목록 복귀.

## 상단 (Hero)

```
● odyssey-1  [ODYSSEY]                    ● UP · 실행 중   [1분 ▾] [⟳]
  고객사 A고객사 · 버전 v1.2.0 · 담당자 admin@a.co.kr
                                          마지막 하트비트 12초 전
┌────────────┬─────────────┬─────────────┬──────────────┐
│ 오늘 에러    │ 이벤트 (24h) │ 가동률 (24h) │ 세션 수       │
│    0        │     14      │   99.7 %    │    5         │
│ 없음        │시작2·종료1   │ 중단 없음    │문자3·RCS2·카카오0│
└────────────┴─────────────┴─────────────┴──────────────┘
```

* 상태 배지: `UP · 실행 중` / `DOWN · 점검 필요`
* Cypher가 `STALE`·`UNKNOWN`이면 상태 배지 옆에 **주황/회색 경고 배지**가 뜨고, 누르면 아래 Cypher 카드로 스크롤합니다.

### KPI 4개

| KPI | 내용 |
| --- | --- |
| **오늘 에러** | 오늘 날짜의 에러 건수 + `CRITICAL n · ERROR n` |
| **이벤트 (24h)** | 이벤트 수 + `시작 n · 종료 n · 타임아웃 n` |
| **가동률 (24h)** | 아래 주의 참고 |
| **네 번째** | 서비스에 따라 다름 — CS: `머신 / 앱`, TWOWAY: `tw 계정`, 그 외: `세션 수` |

{% hint style="danger" %}
**가동률(24h)은 실제 측정치가 아니라 추정치입니다.** 최근 24시간의 종료·타임아웃 이벤트 **1건당 5분 중단**으로 계산합니다. 실제 중단 시간과 다를 수 있으므로 **고객에게 이 숫자를 그대로 인용하지 마십시오.** 실제 중단 구간은 `이벤트` 탭에서 시작·종료 시각을 직접 보고 판단합니다.
{% endhint %}

## 탭 구성

| 탭 | 항상 있음? | 내용 |
| --- | --- | --- |
| **개요** | ✅ | 기본 정보 + 서비스별 연동 정보 + Cypher 에이전트 |
| **이벤트** | ✅ (건수 배지) | 기동·종료·타임아웃·복구 이력 |
| **에러** | ✅ (건수 배지) | 예외 목록 + 스택트레이스 |
| **tw 계정** | TWOWAY만 | 수신 URL, twKeys 목록 |
| **세션 정보** | ODYSSEY·M2X만 (CS는 없음) | 채널별 세션 목록 |

## 개요 탭

### 기본 정보 카드

인스턴스 ID, 고객사, 서비스 타입, 인스턴스명, 버전, (CS면 머신 UUID), 담당자 이메일, 마지막 하트비트.

{% hint style="success" %}
**인스턴스 ID는 개발팀 에스컬레이션 시 반드시 첨부하십시오.** 고객사명·인스턴스명보다 이 번호가 정확합니다.
{% endhint %}

### 서비스별 카드

| 서비스 | 카드 | 내용 |
| --- | --- | --- |
| **ODYSSEY** | 세션 정보 | 문자(MSG) / RCS / 카카오(KAKAO) 각각의 **전송 규격**과 세션 목록(`계정ID #순번`) |
| **TWOWAY** | 수신 설정 | SMS·LMS·MMS·RCS 수신 on/off + **수신 URL(recvUrl)** |
| **CS** | CS 머신 / 계정 정보 | OS, 앱 버전, 머신 UUID / KT Communize ID, RCS Biz Client ID |

{% hint style="info" %}
CS 카드에는 `계정 식별자만 저장됩니다. 비밀번호/시크릿은 전송되지 않습니다.` 라는 문구가 있습니다. 보안 문의 시 그대로 인용할 수 있습니다.
{% endhint %}

### Cypher 에이전트 카드

오류 수집 모듈의 상태입니다. **관제 측 토글은 없고 자동 감지**입니다.

| 상황 | 화면 |
| --- | --- |
| 신호 없음 | `Cypher 신호가 아직 감지되지 않았습니다.` — 고객사가 Cypher를 켜고 첫 신호가 오면 자동 표시 |
| `CONNECTED` | 정상 |
| `STALE` | 주황 배너 — *에이전트 응답이 임계 시간 이상 없습니다. Cypher 프로세스 중단 또는 네트워크 문제 가능성.* |
| `UNKNOWN` | 회색 배너 — *상태를 확인할 수 없습니다. 첫 하트비트 대기 중이거나 연결이 끊긴 상태.* |

모드에 따라 보이는 항목이 다릅니다.

| 항목 | EMBEDDED | SIDECAR |
| --- | --- | --- |
| 호스트 | ✅ | ✅ |
| 마지막 하트비트 | ✅ | ✅ |
| 로그 파일 경로 | — | ✅ |
| 마지막 `.alive` 체크 | — | ✅ |
| 마지막 로그 활동 | — | ✅ |

{% hint style="warning" %}
`마지막 .alive 체크`는 **M2X의 UP/DOWN 판정에 직접 쓰이는 신호**입니다. M2X가 DOWN인데 원인을 모르겠으면 이 값부터 보십시오 ([11. 상태 판정 기준](../part-3/11.-status.md)).
{% endhint %}

## 이벤트 탭

이 인스턴스의 이벤트만 최대 50건. 상단에서 **이벤트 타입**과 **심각도**로 필터할 수 있습니다. 시간대별(`방금 전` / `오늘 오전` / …)로 묶여 표시됩니다.

## 에러 탭 — 장애 원인 파악의 핵심

```
┌────────────────────────────────────────────────────────────────┐
│  24 전체   3 CRITICAL   21 ERROR              12분 전 최근 발생  │
│  이 인스턴스의 에러는 [EMBEDDED] 모드 Cypher로 수집됩니다.        │
├────────────────────────────────────────────────────────────────┤
│ 시간 [최근 1h][24h][7d][전체]                    필터링 8 / 24건 │
│ 심각도[전체▾] 서브시스템[전체▾] 검색[예외 클래스·메시지] [필터 초기화]│
├────────────────────────────────────────────────────────────────┤
│ ●ERROR  java.net.SocketTimeoutException  ×12  ODYSSEY_SEND  ▾  │
│         Read timed out                              12분 전 발생 │
└────────────────────────────────────────────────────────────────┘
```

### 요약 줄

전체 / CRITICAL / ERROR 건수와 최근 발생 시각. Cypher가 붙어 있으면 **어느 모드로 수집 중인지** 한 줄로 알려줍니다.

### 필터

| 필터 | 값 | 비고 |
| --- | --- | --- |
| 시간 | `최근 1h` / `24h` / `7d` / `전체` | **기본값이 `24h`** — 오래된 에러를 찾을 땐 `전체`로 바꾸십시오 |
| 심각도 | `전체` / `CRITICAL` / `ERROR` | |
| 서브시스템 | 수신된 값에서 자동 생성 | 발생 구간 좁히기용 |
| 검색 | 예외 클래스 · 메시지 키워드 | |

`필터 초기화`는 기본값과 다른 필터가 걸려 있을 때만 나타납니다.

{% hint style="warning" %}
기본이 **24시간**이라 "에러가 없다"고 보이는 경우가 있습니다. 며칠 전 장애를 조사할 때는 반드시 `7d` 또는 `전체`로 바꾸십시오.
{% endhint %}

### 에러 한 건 펼치기

행을 클릭하면 펼쳐집니다.

| 항목 | 내용 |
| --- | --- |
| **메시지** | 예외 메시지 전문 |
| **스택 트레이스** | 우리 코드(`com.poseidon.*`) 프레임만 먼저 표시. `system 프레임 N개 표시`를 눌러 나머지를 봅니다 |
| **발생 시각** | 절대 시각 |

`×12` 배지는 **동일 에러 12건이 묶인 것**(coalescing)입니다. 자세한 내용은 [12. 오류 수집 구조](../part-3/12.-errors.md).

{% hint style="danger" %}
**"에러 12건"이 아니라 "같은 에러가 12번 반복"입니다.** 고객에게 전달할 때 표현을 정확히 하십시오.
{% endhint %}

## tw 계정 탭 (TWOWAY)

수신 URL(`recvUrl`)과 **tw 계정(twKeys)** 목록. 각 계정 카드에 활성 수신 채널이 함께 표시됩니다.

## 세션 정보 탭 (ODYSSEY · M2X)

채널 3개(문자 / RCS / 카카오)를 카드로 나누고, 채널별 **전송 규격**과 세션 목록(`계정ID #순번`)을 보여줍니다. 세션이 없으면 `등록된 세션이 없습니다`.
