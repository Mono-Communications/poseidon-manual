# 7. 인스턴스 관리 (ADMIN)

<mark style="color:red;">**`/admin-instances`**</mark> — **인스턴스를 승인하고 API 키를 발급하는 화면.** 고객지원팀이 연동 과정에서 실제로 "처리"하는 가장 중요한 화면입니다.

{% hint style="danger" %}
**ADMIN 전용입니다.** 사이드바에는 USER에게도 메뉴가 보이지만, 클릭하면 무응답입니다.
{% endhint %}

{% hint style="warning" %}
[4. 인스턴스](4.-instances.md)와 이름이 비슷하지만 완전히 다른 화면입니다. 여기는 <mark style="color:red;">`UP/DOWN`</mark>이 아니라 <mark style="color:red;">`PENDING / APPROVED / REVOKED / REJECTED`</mark>를 다룹니다.
{% endhint %}

해지 확인 팝업 문구: _"A고객사 - ODYSSEY" 인스턴스를 해지하시겠습니까? API 키가 비활성화됩니다._

{% hint style="warning" %}
**해지하면 고객사 로그에 인증 실패(`status=401`)가 계속 쌓이고 감시가 끊깁니다.** 운영 중 고객사는 반드시 사전 합의 후 실행하십시오.
{% endhint %}

## <mark style="color:blue;">API 키 발급 모달</mark>

***

**승인·재발급·직접 생성** 시 나타납니다.

<figure><img src="../.gitbook/assets/image (26).png" alt=""><figcaption></figcaption></figure>

{% hint style="danger" %}
**이 창을 닫으면 전체 키를 다시 볼 수 없습니다.** 목록에는 키 접두사만 남습니다. 분실하면 **재발급**밖에 방법이 없습니다. 고객에게 "다시 알려드릴 수 있다"고 말하지 마십시오.
{% endhint %}

### <mark style="color:purple;">모달 동작</mark>

<table><thead><tr><th width="357.75">요소</th><th>동작</th></tr></thead><tbody><tr><td>👁 <strong>아이콘</strong></td><td>키 <strong>가리기 / 보이기</strong> 토글 (어깨너머 노출 방지)</td></tr><tr><td>📋 <strong>아이콘 / <code>키 복사</code></strong></td><td>클립보드 복사 → <mark style="color:$info;"><strong><code>클립보드에 복사되었습니다</code></strong></mark> 표시</td></tr><tr><td><strong>ESC · 바깥 클릭</strong></td><td><strong>닫히지 않습니다</strong> (실수 방지)</td></tr><tr><td><strong><code>닫기</code> (복사 전)</strong></td><td>아래 확인 단계로 넘어감</td></tr><tr><td><strong><code>닫기</code> (복사 후)</strong></td><td>그대로 닫힘</td></tr></tbody></table>

### <mark style="color:purple;">복사하지 않고 닫으려 하면</mark>

**`키를 복사했습니까? 이 화면을 닫으면 키를 다시 볼 수 없습니다.`** 확인이 뜨고 두 가지 버튼이 나옵니다.

<table><thead><tr><th width="362.75">버튼</th><th>동작</th></tr></thead><tbody><tr><td><strong>키 보기</strong></td><td>확인을 취소하고 키 화면으로 돌아감</td></tr><tr><td><strong>닫고 폐기</strong> / <strong>닫기</strong></td><td>아래 참고</td></tr></tbody></table>

{% hint style="danger" %}
**`닫고 폐기`는 인스턴스를 실제로 지웁니다.**

* **방금 `+ 인스턴스 생성`으로 만든 건**이면 버튼이 **`닫고 폐기`** 로 나오고, 누르면 그 인스턴스를 **해지(REVOKED) 후 삭제**합니다. 처음부터 다시 만들어야 합니다.
* **기존 건을 승인·재발급한 경우**에는 버튼이 그냥 **`닫기`** 이고, 인스턴스는 유지됩니다(키만 다시 볼 수 없게 됨).

버튼 글자를 꼭 확인하고 누르십시오.
{% endhint %}

## <mark style="color:blue;">**인스턴스 직접 생성**</mark>

***

고객사가 등록 요청을 보내기 전에 우리가 먼저 만들어 키를 전달할 때 씁니다.

우측 상단 <mark style="color:$info;">**`+ 인스턴스 생성`**</mark> → 고객사와 서비스를 선택 → <mark style="color:$info;">**`생성`**</mark>

| 입력      | 값                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **고객사** | 등록된 고객사 목록에서 선택 (필수)                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **서비스** | <mark style="color:red;">`ODYSSEY`</mark> <mark style="color:red;"></mark><mark style="color:red;">/</mark> <mark style="color:red;"></mark><mark style="color:red;">`TWOWAY`</mark> <mark style="color:red;"></mark><mark style="color:red;">/</mark> <mark style="color:red;"></mark><mark style="color:red;">`CS`</mark> <mark style="color:red;"></mark><mark style="color:red;">/</mark> <mark style="color:red;"></mark><mark style="color:red;">`M2X`</mark> |

> 고객사와 서비스를 선택하면 **즉시 `APPROVED` 상태로 생성되고 API 키가 발급됩니다.**

{% hint style="info" %}
호스트명·로그 파일 경로 등은 **입력하지 않습니다.** M2X를 포함한 모든 서비스에서 **첫 하트비트가 도착할 때 자동으로 수집**됩니다.
{% endhint %}

## <mark style="color:blue;">전형적인 작업 흐름</mark>

***

```
① 고객사 등록          → [6. 고객사] + 고객사 등록
② 인스턴스 확보
   ├─ 고객사가 요청한 경우 → PENDING 건을 [승인]
   └─ 우리가 먼저 만드는 경우 → [+ 인스턴스 생성]
③ API 키 발급 모달에서 [키 복사]  ← 반드시 복사 후 닫기
④ 안전한 채널로 고객사에 전달
⑤ 고객사 설정 + 재시작
⑥ [4. 인스턴스] 화면에서 UP 확인
```

전체 절차는 [13. 고객 온보딩 절차](../part-4/13.-onboarding.md)를 참고하십시오.<br>

## <mark style="color:blue;">자주 하는 실수</mark>

***

| 실수                                       | 결과                                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| **키를 복사하지 않고 모달을 닫음**                    | 재발급 필요 (신규 생성 건이면 인스턴스가 삭제될 수도 있음)                                                       |
| **키를 메일 본문에 그대로 붙여 전달**                  | 키는 인증 수단 그 자체 — 보안 사고                                                                    |
| **HA 고객사인데 인스턴스를 1개만 만듦**                | 한쪽 노드만 감시됨                                                                               |
| **이 화면의 `APPROVED`를 보고 "정상 가동 중"이라고 답변** | <mark style="color:red;">`APPROVED`</mark>는 등록 상태일 뿐 — 가동 여부는 [4. 인스턴스](4.-instances.md) |
