# 7. 인스턴스 관리 (ADMIN)

`/admin-instances` — **인스턴스를 승인하고 API 키를 발급하는 화면.** 고객지원팀이 연동 과정에서 실제로 "처리"하는 가장 중요한 화면입니다.

부제: *인스턴스 승인 / 거절 / 해지 · API 키 발급 · 직접 생성*

{% hint style="danger" %}
**ADMIN 전용입니다.** 사이드바에는 USER에게도 메뉴가 보이지만, 클릭하면 **403 화면**으로 넘어갑니다.
{% endhint %}

{% hint style="warning" %}
[4. 인스턴스](4.-instances.md)와 이름이 비슷하지만 **완전히 다른 화면**입니다. 여기는 `UP/DOWN`이 아니라 `PENDING / APPROVED / REVOKED / REJECTED`를 다룹니다. 자동 갱신도 없습니다(`새로고침` 버튼 사용, 작업 후에는 자동 재조회).
{% endhint %}

## 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│ 인스턴스 관리                              [⟳ 새로고침] [+ 인스턴스 생성]│
├──────────────────────────────────────────────────────────────────────┤
│ ⏱ 2개의 인스턴스가 승인 대기 중입니다               [검토하기 →]        │
│   신규 가입한 고객사 인스턴스를 검토하고 API 키를 발급해 주세요.         │
├───────────────┬───────────────┬───────────────┬──────────────────────┤
│ ▤ 전체 12     │ ✓ 승인 9 75%  │ ⏱ 대기 2 16.7%│ ✕ 해지/거절 1  8.3%  │
├───────────────┴───────────────┴───────────────┴──────────────────────┤
│ 🔍 고객사, 키 접두사 검색                                              │
├────┬─────────┬─────────┬────────────┬──────────┬────┬────────┬───────┤
│No. │ 고객사   │ 서비스   │ 키 접두사   │ 상태      │활성│ 생성일  │ 작업  │
│ 1  │ A고객사  │ ODYSSEY │ odk_T1va…  │ PENDING  │ ●  │2026-07-│승인 거절│
│ 2  │ B고객사  │ TWOWAY  │ twk_9fKx…  │ APPROVED │ ●  │2026-06-│ 해지  │
│ 3  │ C고객사  │ M2X     │ m2k_3aQd…  │ REVOKED  │ ○  │2026-05-│재발급 삭제│
└────┴─────────┴─────────┴────────────┴──────────┴────┴────────┴───────┘
```

### 승인 대기 배너

`PENDING`이 1건 이상일 때만 상단에 나타납니다. `검토하기 →`를 누르면 **PENDING만 필터링**된 목록으로 바뀝니다.

{% hint style="success" %}
**업무 시작 시 이 배너부터 확인하십시오.** 고객사가 연동을 시작했는데 승인이 안 돼 대기 중일 수 있습니다.
{% endhint %}

### 상단 4칸 — 클릭하면 필터

| 칸 | 대상 |
| --- | --- |
| **전체 인스턴스** | 필터 해제 |
| **승인 (APPROVED)** | 승인 완료 건 |
| **대기 (PENDING)** | 승인 대기 건 |
| **해지 / 거절** | `REVOKED` + `REJECTED` |

### 테이블 열

| 열 | 내용 |
| --- | --- |
| **No.** | 화면상 순번 |
| **고객사** | 고객사명 |
| **서비스** | `ODYSSEY` / `TWOWAY` / `CS` / `M2X` |
| **키 접두사** | API 키의 앞부분만. **전체 키는 여기서 볼 수 없습니다** |
| **상태** | `PENDING` / `APPROVED` / `REVOKED` / `REJECTED` |
| **활성** | 점 표시 (● 활성 / ○ 비활성) |
| **생성일** | 날짜 + 시각 |
| **작업** | 상태에 따라 버튼이 달라짐 (아래) |

검색은 **고객사명과 키 접두사**를 대상으로 합니다.

## 상태별 작업 버튼

| 현재 상태 | 버튼 | 결과 |
| --- | --- | --- |
| `PENDING` | **승인** | `APPROVED` 전환 + **API 키 발급 모달** |
| `PENDING` | **거절** | `REJECTED` 전환 |
| `APPROVED` | **해지** | 확인 팝업 → `REVOKED` 전환, **API 키 비활성화** |
| `REVOKED` | **재발급** | 새 API 키 발급 + **발급 모달** |
| `REVOKED` | **삭제** | 확인 팝업 → 인스턴스 삭제 |
| 그 외 | `—` | 작업 없음 |

해지 확인 팝업 문구: *"A고객사 - ODYSSEY" 인스턴스를 해지하시겠습니까? API 키가 비활성화됩니다.*

{% hint style="warning" %}
**해지하면 고객사 로그에 인증 실패(`status=401`)가 계속 쌓이고 감시가 끊깁니다.** 운영 중 고객사는 반드시 사전 합의 후 실행하십시오.
{% endhint %}

## API 키 발급 모달 — 이 시스템에서 가장 중요한 화면

승인·재발급·직접 생성 시 나타납니다.

```
┌─────────────────────────────────────────────────────┐
│ 🔑 API 키 발급                                    ✕  │
├─────────────────────────────────────────────────────┤
│ ⚠ 이 화면을 닫으면 키를 다시 볼 수 없습니다.            │
│   안전한 채널로 고객사에 전달했는지 확인하세요.          │
│                                                     │
│  odk_T1vaQ9xMz3kP8sLr2WnB6cYf         [👁] [📋]     │
│                                                     │
│  ✓ 클립보드에 복사되었습니다                            │
├─────────────────────────────────────────────────────┤
│                              [닫기]  [📋 키 복사]     │
└─────────────────────────────────────────────────────┘
```

{% hint style="danger" %}
**이 창을 닫으면 전체 키를 다시 볼 수 없습니다.** 목록에는 키 접두사만 남습니다. 분실하면 **재발급**밖에 방법이 없습니다. 고객에게 "다시 알려드릴 수 있다"고 말하지 마십시오.
{% endhint %}

### 모달 동작

| 요소 | 동작 |
| --- | --- |
| 👁 아이콘 | 키 **가리기 / 보이기** 토글 (어깨너머 노출 방지) |
| 📋 아이콘 / `키 복사` | 클립보드 복사 → `클립보드에 복사되었습니다` 표시 |
| ESC · 바깥 클릭 | **닫히지 않습니다** (실수 방지) |
| `닫기` (복사 전) | 아래 확인 단계로 넘어감 |
| `닫기` (복사 후) | 그대로 닫힘 |

### 복사하지 않고 닫으려 하면

`키를 복사했습니까? 이 화면을 닫으면 키를 다시 볼 수 없습니다.` 확인이 뜨고 두 가지 버튼이 나옵니다.

| 버튼 | 동작 |
| --- | --- |
| **키 보기** | 확인을 취소하고 키 화면으로 돌아감 |
| **닫고 폐기** / **닫기** | 아래 참고 |

{% hint style="danger" %}
**`닫고 폐기`는 인스턴스를 실제로 지웁니다.**

* **방금 `+ 인스턴스 생성`으로 만든 건**이면 버튼이 **`닫고 폐기`** 로 나오고, 누르면 그 인스턴스를 **해지(REVOKED) 후 삭제**합니다. 처음부터 다시 만들어야 합니다.
* **기존 건을 승인·재발급한 경우**에는 버튼이 그냥 **`닫기`** 이고, 인스턴스는 유지됩니다(키만 다시 볼 수 없게 됨).

버튼 글자를 꼭 확인하고 누르십시오.
{% endhint %}

## 인스턴스 직접 생성

고객사가 등록 요청을 보내기 전에 우리가 먼저 만들어 키를 전달할 때 씁니다.

우측 상단 `+ 인스턴스 생성` → 고객사와 서비스를 선택 → `생성`.

| 입력 | 값 |
| --- | --- |
| **고객사** | 등록된 고객사 목록에서 선택 (필수) |
| **서비스** | `ODYSSEY` / `TWOWAY` / `CS` / `M2X` |

> 고객사와 서비스를 선택하면 **즉시 `APPROVED` 상태로 생성되고 API 키가 발급됩니다.**

{% hint style="info" %}
호스트명·로그 파일 경로 등은 **입력하지 않습니다.** M2X를 포함한 모든 서비스에서 **첫 하트비트가 도착할 때 자동으로 수집**됩니다.
{% endhint %}

## 전형적인 작업 흐름

```
① 고객사 등록          → [6. 고객사] + 고객사 등록
② 인스턴스 확보
   ├─ 고객사가 요청한 경우 → PENDING 건을 [승인]
   └─ 우리가 먼저 만드는 경우 → [+ 인스턴스 생성]
③ API 키 발급 모달에서 [키 복사]  ← 반드시 복사 후 닫기
④ 안전한 채널로 고객사에 전달
⑤ 고객사 설정 + 재시작
⑥ [4. 인스턴스] 화면에서 UP 확인
```

전체 절차는 [13. 고객 온보딩 절차](../part-4/13.-onboarding.md)를 참고하십시오.

## 자주 하는 실수

| 실수 | 결과 |
| --- | --- |
| 키를 복사하지 않고 모달을 닫음 | 재발급 필요 (신규 생성 건이면 인스턴스가 삭제될 수도 있음) |
| 키를 메일 본문에 그대로 붙여 전달 | 키는 인증 수단 그 자체 — 보안 사고 |
| HA 고객사인데 인스턴스를 1개만 만듦 | 한쪽 노드만 감시됨 |
| 이 화면의 `APPROVED`를 보고 "정상 가동 중"이라고 답변 | `APPROVED`는 등록 상태일 뿐 — 가동 여부는 [4. 인스턴스](4.-instances.md) |
