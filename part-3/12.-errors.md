# 12. 오류 수집 구조와 Cypher

인스턴스 상세의 **`에러` 탭**이 어떻게 채워지는지, 왜 어떤 건 안 올라오는지를 설명합니다.

## <mark style="color:blue;">어떻게 수집되는가</mark>

***

고객사 엔진 안(또는 옆)에는 **Cypher**라는 오류 수집 모듈이 함께 동작합니다. 별도 에이전트 설치나 로그 파일 전송 없이, 엔진이 남기는 **ERROR / FATAL 로그를 가로채** **Poseidon**으로 보고합니다.

```
엔진 로그 발생 (ERROR/FATAL)
      │
      ├─ 발생 단계(서브시스템) 자동 분류
      ├─ 심각도 변환 (ERROR→ERROR, FATAL→CRITICAL)
      ├─ 동일 오류 30초 단위 묶음 처리
      ▼
 Poseidon 오류 보고 ──► DB 저장 ──► 인스턴스 상세 '에러' 탭
                                  + 이벤트 '에러 수신' + 알림
```

* <mark style="color:red;">`WARN`</mark> 이하 로그는 **수집 대상이 아닙니다.**
* 고객이 <mark style="color:red;">`poseidon.cypher.enabled: false`</mark> 로 설정하면 오류 수집만 끄고 상태·지표는 유지할 수 있습니다.<br>

## <mark style="color:blue;">Cypher 두 가지 모드</mark>

***

화면(**인스턴스 상세 → 개요 → Cypher 에이전트** 카드)에서 어느 모드인지 바로 보입니다. **`에러`** 탭 상단에도 **` 이 인스턴스의 에러는`` `**` `<mark style="color:red;">`[EMBEDDED]`</mark>**` ``모드`` `**<mark style="color:red;">`Cypher`</mark>**`로 수집됩니다.`** 처럼 표시됩니다.

## <mark style="color:blue;">**서브시스템 (발생 단계)**</mark>

***

오류가 어느 기능 영역에서 났는지 자동 분류된 값입니다. **원인 구간을 좁히는 데 가장 유용한 정보**이며, `에러` 탭에서 필터로 쓸 수 있습니다(수신된 값만 목록에 나타납니다).

| 서브시스템                    | 의미            | 흔한 원인                       |
| ------------------------ | ------------- | --------------------------- |
| **`ODYSSEY_SEND`**       | 메시지 발송 단계     | 게이트웨이 응답 실패, 타임아웃           |
| **`ODYSSEY_NETWORK`**    | 게이트웨이 HTTP 통신 | 대외 연동 구간 장애, 인증 만료, DNS·방화벽 |
| **`ODYSSEY_DB`**         | DB 접근         | 커넥션 부족, 데드락, 쿼리 오류          |
| **`ODYSSEY_COLLECT`**    | 발송 대상 수집      | DB 지연, 테이블·컬럼 설정 문제         |
| **`ODYSSEY_FETCH`**      | 메시지 폴링        | 폴링 쿼리 오류, DB 부하             |
| **`ODYSSEY_ROUTE`**      | 채널 라우팅        | 세션·계정 매핑 불일치                |
| **`ODYSSEY_REPORT`**     | 발송 결과 반영      | 결과 업데이트 실패                  |
| **`ODYSSEY_AUTH`**       | 세션 인증         | 인증 파일(`.cert`)·계정 정보 문제     |
| **`ODYSSEY_SCHEDULER`**  | 스케줄러          | 주기 작업 실패                    |
| **`ODYSSEY_MONITORING`** | 모니터링 모듈       | 지표 수집 자체의 오류                |
| **`ODYSSEY_STAT`**       | 통계 집계         | 집계 처리 실패                    |
| **`ODYSSEY_SHUTDOWN`**   | 종료 처리         | 종료 중 예외                     |
| **`ODYSSEY_CHARON`**     | Charon 모듈     | 해당 모듈 오류                    |
| **`ODYSSEY_PIPELINE`**   | 위에 해당하지 않는 전반 | 기타                          |

## <mark style="color:blue;">묶음 처리— 건수가 실제와 다른 이유</mark>

***

동일한 오류가 폭주하면 **30초 윈도 안의 같은 오류를 1건으로 묶어** 보고합니다. 화면에서는 `×12` 같은 배지로 표시되고, 마우스를 올리면 <mark style="color:red;">`동일 에러 12건 묶음 (coalesced)`</mark> 툴팁이 나옵니다.

| 실제 상황                            | 화면에 보이는 것                 |
| -------------------------------- | ------------------------- |
| **DB 커넥션 장애로 같은 예외가 초당 수백 건 발생** | 30초 간격으로 1건씩, `×N` 배지에 누적 |
| **서로 다른 예외 3종이 발생**              | 3건 각각 표시                  |

{% hint style="info" %}
그래서 **화면의 에러 건수 ≠ 실제 발생 횟수** 입니다. 고객에게 "3건 발생했습니다"라고 말하지 말고 **"3종류의 오류가 반복 발생했습니다"** 로 전달하십시오.
{% endhint %}

## <mark style="color:blue;">**수집되는 항목 / 수집되지 않는 항목**</mark>

***

**\[수집되는 것]**

| 항목            | 예                                                                                                                    |
| ------------- | -------------------------------------------------------------------------------------------------------------------- |
| **심각도**       | <mark style="color:red;">`ERROR`</mark> <mark style="color:red;">/</mark> <mark style="color:red;">`CRITICAL`</mark> |
| **서브시스템**     | <mark style="color:red;">**`ODYSSEY_SEND`**</mark>                                                                   |
| **예외 클래스**    | <mark style="color:red;">**`java.net.SocketTimeoutException`**</mark>                                                |
| **예외 메시지**    | 로그에 기록된 메시지                                                                                                          |
| **스택트레이스 요약** | 발생 지점 식별용 요약 (전문 아님)                                                                                                 |
| **발생 시각**     | 최초 발생 시각                                                                                                             |
| **발생 횟수**     | 묶음 처리된 건수 (`×N`)                                                                                                     |

**\[수집되지 않는 것]**

{% hint style="success" %}
수신자 전화번호, 메시지 본문, 발송 대상 데이터, 고객사 DB 레코드, DB·게이트웨이 계정 **비밀번호/시크릿**은 **전송 항목에 없습니다.**

(CS 서비스의 경우 화면에도 명시되어 있습니다 — _계정 식별자만 저장됩니다. 비밀번호/시크릿은 전송되지 않습니다._)
{% endhint %}
