# 9. 시스템 구성과 데이터 흐름

화면에 숫자가 왜 그렇게 나오는지, 고객 질문에 왜 그렇게 답해야 하는지는 이 구조를 알아야 설명할 수 있습니다.

## 전체 구성

```
 [고객사 내부망]                            │        [모노 클라우드]
                                           │
 ┌────────────────────────┐   Outbound     │   ┌──────────┐   ┌─────────────┐
 │ Odyssey 발송 엔진        │  HTTP(S)       │   │ Gateway  │──►│ poseidon-api │
 │  + Cypher (오류 수집)    │ ─────────────► │──►│ (인증)    │   │  + DB        │
 └────────────────────────┘                │   └──────────┘   └──────┬───────┘
        ▲                                  │                          │
        │ 발송                              │            ┌─────────────┴──────────┐
 ┌──────┴──────┐                           │            ▼                        ▼
 │  고객사 DB   │                           │      Poseidon 웹 화면        RabbitMQ → Rust
 └─────────────┘                           │      (상태·오류 목록)         → Prometheus (지표)
                                           │
                                           │   ※ Poseidon → 고객사 방향 접속은 없음
```

### 고객사 쪽 (설치되는 것)

| 이름                | 정체                                        | 역할                                    |
| ----------------- | ----------------------------------------- | ------------------------------------- |
| **Odyssey**       | 문자 발송 엔진 (Java)                           | 실제 발송 + 기동·하트비트·종료 신호 전송              |
| **Cypher (임베디드)** | 네이티브 라이브러리 (`cypher.dll` / `libcypher.so`) | Odyssey 로그의 ERROR/FATAL을 가로채 오류 보고. Odyssey와 같은 프로세스 |
| **Cypher (사이드카)** | 별도 프로세스                                   | 레거시 제품(M2X)에 붙여 로그 파일을 감시             |
| **Twoway**        | 수신(양방향) 엔진                                | Odyssey와 동일한 방식으로 연동                  |

### 우리 쪽

| 이름               | 역할                                            |
| ---------------- | --------------------------------------------- |
| **Gateway**      | 외부 진입점. 고객이 보낸 인증 키를 검증해 고객사·인스턴스 식별값으로 변환     |
| **poseidon-api** | 본체. 인스턴스 등록, 하트비트·오류 저장, 상태 판정, 알림 발행, 지표 중계  |
| **DB**           | 인스턴스·오류·이벤트 이력 저장 → **웹 화면이 보여주는 데이터**        |
| **RabbitMQ → Rust → Prometheus** | 지표(그래프) 전용 경로                    |
| **Poseidon 웹**   | 고객지원팀이 보는 화면                                  |

{% hint style="warning" %}
**상태·오류와 지표는 경로가 다릅니다.** 상태·오류는 poseidon-api → DB → 화면으로 흐르고, 지표(그래프)는 RabbitMQ → Rust → Prometheus로 흐릅니다. 그래서 **"상태는 UP인데 지표 그래프만 비어 있는"** 상황이 생길 수 있고, 이건 고객사 문제가 아니라 우리 쪽 지표 파이프라인 문제일 수 있습니다 ([15. 플레이북](../part-4/15.-playbook.md) 참조).
{% endhint %}

## 고객사가 보내는 신호 4가지

| 시점         | 신호        | 형식              | 화면에 반영되는 곳                      |
| ---------- | --------- | --------------- | ------------------------------- |
| 기동 시 1회    | **기동 등록** | JSON            | 대시보드·모니터링 목록에 인스턴스가 나타남         |
| **30초마다**  | **하트비트**  | 바이너리(지표 동봉)     | 상태 `UP` 유지, `마지막 하트비트` 갱신, 지표 그래프 |
| 종료 시 1회    | **종료 알림** | JSON            | 상태 전환 (계획된 종료로 기록, 장애 알림 아님)    |
| 오류 발생 시    | **오류 보고** | JSON            | 인스턴스 상세의 **오류 로그** 표           |

* 인증은 요청마다 **인증 키(API Key) 헤더 1개**로 이루어집니다. 고객사에 별도 인증서·VPN·계정은 필요 없습니다.
* 하트비트 1회 크기는 **300\~500바이트**, 트래픽은 **하루 약 1\~1.5MB** 입니다.
* 전송 실패는 고객사 로그에 경고만 남고 **발송에는 영향이 없습니다**(다음 주기에 재시도).

## 순서대로 보면

```
1) 고객사가 Odyssey 기동
      │
      ├─► 기동 등록 전송 ──► Gateway 인증 ──► DB 등록
      │                                        └─► 화면에 인스턴스 등장 (UP)
      │
2) 이후 30초마다
      ├─► 하트비트 + 지표 ──► 마지막 하트비트 시각 갱신
      │                        └─► 지표는 RabbitMQ로 넘겨 그래프로
      │
3) ERROR/FATAL 로그 발생 시
      ├─► 오류 보고 ──► 오류 저장 + 이벤트 생성 ──► 알림 발송
      │                                            └─► 상세 화면 오류 로그에 표시
      │
4) 3분 넘게 하트비트가 안 오면
      └─► 서버가 자체 판단으로 DOWN 처리 + 장애 알림
```

## 고객이 자주 묻는 것과 답

| 질문                     | 답                                                            |
| ---------------------- | ------------------------------------------------------------ |
| "저희 서버에 들어오는 건가요?"     | 아닙니다. 고객사 → Poseidon **단방향**입니다. 인바운드 개방이 필요 없습니다            |
| "원격으로 제어하나요?"          | 명령을 내리는 기능이 없습니다. 받기만 합니다                                    |
| "발송 데이터가 나가나요?"        | 집계 수치와 예외 정보만 나갑니다. 수신번호·메시지 본문·DB 레코드는 전송 항목에 없습니다          |
| "우리 DB에 접근하나요?"        | 접근하지 않습니다. Odyssey가 이미 가진 지표를 요약해 보내는 것뿐입니다                  |
| "실시간인가요?"              | 30초 주기입니다. 장애 인지에는 최대 3\~4분이 걸립니다                            |
| "연동이 끊기면 발송이 멈추나요?"    | 멈추지 않습니다. 지표·감시만 중단됩니다                                       |
